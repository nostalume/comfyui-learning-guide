# ComfyUI 学习指南

一套从零讲到团队落地的 ComfyUI 中文学习材料 —— 不罗列节点与参数，而是讲清一个节点为什么会存在。

- 🌐 **在线阅读：** https://nostalume.github.io/comfyui-learning-guide/
- 📄 **许可证：** MIT（见 [`LICENSE`](LICENSE)）

这个仓库有两类使用者，各看一节：

| 你是谁 | 看哪节 |
|---|---|
| **读者** —— 来学 ComfyUI 的 | [读者](#读者) |
| **开发者** —— 来维护文档或站点的 | [开发者](#开发者) |

### 怎么开始

**完全没接触过 AI 绘图** —— 从 [0.1 什么是 AI 图像生成](src/content/docs/0-零基础入门/0.1-什么是AI图像生成.md) 开始，按顺序往下读。第 0–3 章是一条完整路径，走完能独立完成文生图与图生图。

**用过 WebUI，想转 ComfyUI** —— 先看 [0.3 与 WebUI 的差异对比](src/content/docs/0-零基础入门/0.3-与WebUI的差异对比.md)。两者的差别在思维方式：WebUI 是填表单，ComfyUI 是连数据流。然后从安装章节接回主线。

**只是想查东西**：

| 想查什么 | 去哪 |

| 某个节点的中文名（软件界面是英文的） | [A2 节点名称中英对照](src/content/docs/附录/A2-节点名称中英对照.md) |
| 某个术语是什么意思 | [A1 术语对照表](src/content/docs/附录/A1-术语对照表.md)。它不是词汇表 —— 只告诉你这个词由哪一篇推导出来，再回那一篇去读 |
| 提示词技巧、版本差异、模型清单、安装参数 | [A3](src/content/docs/附录/A3-提示词技巧速查.md)、[A4](src/content/docs/附录/A4-版本差异指南.md)、[A5](src/content/docs/附录/A5-模型与工具清单.md)、[A6](src/content/docs/附录/A6-安装部署参考.md) |

### 读的时候要知道的几件事

**内容是从第一性原理推导出来的**，不是节点字典：

| 原则 | 含义 |
|---|---|
| 提纲挈领 | 不求面面俱到，只留下推理链上必要的概念 |
| 兼容两类读者 | 熟悉的人能快速定位，不熟悉的人能不跳跃地跟上 |
| 概念之间有推导链接 | 每个概念的出现都有上一步的动机 |
| 术语是推导的结果 | 不先抛术语再解释 |
| 双向自洽 | 每篇都能接上前面，自身也讲得通 |

> 这条原则的强度按文章类型分级：讲原理的按全强度写；教操作的不强制推导，步骤本身就是清单；查阅型的只保证不罗列无用信息，不在里面重复推导。

**`<ComfyUI 目录>` 是占位符**，不是固定名字 —— 按你自己实际的安装位置理解。

**网址里的章节号不带点号**：`1.6-连线逻辑` 的地址是 `/16-连线逻辑/`；目录名里的大写字母会转小写（`4-ControlNet精准控制` → `/4-controlnet精准控制/`）。这是生成网址时的标准行为，站内跳转不受影响。

## 开发者

### 工具

只需要两个：**Node.js 20+** 与 **pnpm 9+**。

```bash
pnpm install
```

> 首次安装后如果构建报原生模块缺失，执行 `pnpm approve-builds --all`，允许 `sharp` / `esbuild` 执行安装脚本。

### 命令

| 用途 | 命令 |
|---|---|
| 开发服务器（热更新） | `pnpm dev` |
| 构建站点 | `pnpm build` |
| 预览构建产物 | `pnpm preview` |
| 类型与内容校验 | `pnpm check` |
| 校验产物里的内部链接 | `pnpm check:links` |
| 清空 `dist/` | `pnpm clean` |
| 清空 `dist/` 与 Astro 缓存 | `pnpm clean:cache` |

常用的组合：

| 场景 | 命令 |
|---|---|
| 写内容，边写边看效果 | `pnpm dev` |
| 改完内容，提交前 | `pnpm build && pnpm check:links` |
| 改了 `src/plugins/**` 但构建结果没变化 | `pnpm clean:cache && pnpm build` |
| 只想知道链接有没有写坏 | `pnpm check:links`（只读 `dist/`，约两秒） |

> `build` 不是单纯执行 `astro build`，而是 `clean.mjs && astro build`：先清空 `dist/`，再交给 Astro。这样做是因为 `check:links` 与搜索索引都只读 `dist/` —— 已删掉的页面如果还留在那里，会把结论带偏。
>
> **判断构建成功与否，只看退出码。** 别用 `pnpm build | tail`：管道的退出码来自 `tail`，失败会被读成成功。

### 目录结构

```
.
├── astro.config.mjs          站点配置：地址、语言、侧边栏、搜索、链接重写插件
├── tsconfig.json
├── pnpm-workspace.yaml       允许 sharp / esbuild 执行安装脚本
├── public/favicon.svg
├── scripts/
│   ├── clean.mjs             清空 dist/（可选连 Astro 内容缓存一起清）
│   └── check-links.mjs       校验构建产物里的内部链接
└── src/
    ├── content.config.ts     内容集合定义
    ├── plugins/remark-relative-links.mjs   构建期把相对 .md 链接改写成站内路由
    ├── styles/custom.css     中文排版微调
    └── content/docs/         全部文档
        ├── 0-零基础入门/ … 9-团队知识库与任务管理/    正篇十章
        ├── 实战案例/          Level 1–5
        └── 附录/              A1–A8
```

> 目录名与站上显示的章名可以不同。站上的章名写在 `astro.config.mjs` 的侧边栏里；目录名保持稳定，因为改它会牵动所有跨目录的相对链接。

### 写内容时的约定

1. **frontmatter 必须有 `title`。** 缺了会报 `title: Required`。
2. **跨文档引用就写相对 `.md` 链接**，例如 `[1.6 节点类型](./1.6-节点类型.md)`。
   - 相对链接在 GitHub 上浏览仓库时本来就是对的，读者点得动。Astro 不会重写它们，所以仓库用 `src/plugins/remark-relative-links.mjs` 在构建时改写成站内地址。
   - 代价是改了插件就要清缓存（`pnpm clean:cache`）；改内容本身不用。
3. **不要写内容里的根相对链接**（如 `/foo/`）。它们不会自动补上站点前缀，部署在子路径下必然 404 —— 要跳转就用第 2 条的相对 `.md`。
4. **侧边栏是自动生成的。** `astro.config.mjs` 里按目录配置，新增文档不用改配置。组内顺序按文件名；需要插队就用 frontmatter 的 `sidebar.order`，需要改显示名就用 `sidebar.label`。
5. **站点是单语言的（中文）。** 中文即默认语言，内容在 `src/content/docs/`。
   - 语言配置里只声明中文，**不声明其他语言**。一旦声明了某种语言却没有对应的内容目录，构建会为每一篇生成一份该语言下的副本，搜索索引也会变成双语言 —— 所以启用新语言时，**内容目录与语言声明要同时加**。
6. **讲概念的正文要带「本文承接 / 本文引出」块**，写明上文哪一篇的哪个概念引出了本文、本文的概念又被下文哪一篇用上。这是整套材料里唯一能被工具检查的连贯性机制，写成引用块，紧跟第一个一级标题。
   - 第 0–9 章全部具备。实战案例、附录、首页不需要：案例是练习，附录是查阅型内容。
7. **代码围栏必须带语言标记，并选对标记。** 灰底方框对读者是三样不同的东西，标错了会误导。

   | 用途 | 标记 | 读者该做什么 |
   |---|---|---|
   | 命令 —— 照着敲 | `bash` / `powershell` | 复制到终端执行 |
   | 代码 —— 读懂即可 | `python` / `json` / `javascript` | 读行尾的中文注释，不要求会写 |
   | 排版示意 —— 目录树、命名模板 | `text` | 只读；`├──` 与 `[占位符]` 都不是命令 |
   | 纯文本 —— 路径、报错、报告输出 | `text` | 只读 |

   判断依据是**第一行是不是一条真命令**，不是「看起来像不像终端里的东西」。
8. **一篇之内不接受「瞬移」。** 一段在讲 A，下一段不能突然开始讲 B，除非中间写明了 B 是从 A 的哪个缺口出来的。
   同类的还有三条能被工具检查的：术语不能用在自己被推导出来之前；代码围栏前面要交代这段在做什么，后面要说明结果意味着什么；每个小节的开头要接得上上一节。
9. **不要在正文里写「文档版本」「更新日期」这类信息块。** 站点已经由「最近更新」提供时间信息，手写的版本号只会随着内容改造变成过期数据。

### 部署

站点发布在 **GitHub Pages**：<https://nostalume.github.io/comfyui-learning-guide/>

推送到 `main` 即触发自动部署（`.github/workflows/deploy.yml`）：安装依赖 → `pnpm build` → 跑
`pnpm check:links` 门禁 → 发布 `dist/`。**门禁不通过时不会覆盖线上版本**，站点保持上一次成功的内容。

首次启用需在仓库设置里做一次：**Settings → Pages → Source** 选 `GitHub Actions`。

站点路径由 `astro.config.mjs` 的 `base` 决定（`/comfyui-learning-guide`），须与仓库名一致。
构建产物在 `dist/`，也可以托管到任意静态服务器。
