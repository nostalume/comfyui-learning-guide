## 一、基础术语

### 1. AI 图像生成 (AI Image Generation)

#### 功能描述
让人工智能根据文字描述生成图片的技术。就像你告诉一个画家你想要什么样的画，画家帮你画出来，只不过这个"画家"是 AI。

#### 使用场景
- 需要快速生成图片素材
- 没有绘画技能但需要创作图像
- 探索创意和设计灵感

#### 相关术语
- 提示词 (Prompt)
- 模型 (Model)
- Stable Diffusion

---

### 2. 提示词 (Prompt)

#### 功能描述
你告诉 AI 的文字描述，用来指导它生成图片。提示词就是你与 AI 沟通的语言，描述得越详细，生成的图片越符合预期。

#### 使用场景
- 文生图时描述想要的画面
- 图生图时描述想要的改变
- 风格迁移时描述目标风格

#### 参数说明
| 参数类型 | 说明 | 示例 |
|---------|------|------|
| 主体描述 | 图片的主要内容 | "a cute cat"（一只可爱的猫）|
| 风格描述 | 图片的艺术风格 | "oil painting style"（油画风格）|
| 质量描述 | 图片的质量要求 | "high quality, detailed"（高质量，细节丰富）|
| 构图描述 | 图片的构图方式 | "close-up, portrait"（特写，肖像）|

#### 示例
```
简单提示词：a cat
详细提示词：a fluffy orange cat sitting on a windowsill, sunlight streaming through, cozy atmosphere, soft lighting, high quality, detailed, photorealistic
```

#### 注意事项
- ⚠️ 建议使用英文提示词，效果通常更好
- ⚠️ 提示词顺序会影响生成结果，重要的词放在前面
- ⚠️ 可以使用权重调整词语重要性，如 `(detailed:1.2)`
- ⚠️ 避免使用相互矛盾的描述

#### 相关术语
- 反向提示词 (Negative Prompt)
- CFG Scale
- 权重 (Weight)

---

### 3. 反向提示词 (Negative Prompt)

#### 功能描述
告诉 AI 不要生成什么内容。就像告诉画家"不要画红色的东西"，AI 会避免生成你描述的内容。

#### 使用场景
- 避免生成不需要的元素
- 提高图片质量
- 排除常见的生成问题

#### 示例
```
常用反向提示词：
low quality, blurry, distorted, ugly, bad anatomy, extra limbs, watermark, text, signature
（低质量、模糊、变形、丑陋、解剖错误、多余肢体、水印、文字、签名）
```

#### 注意事项
- ⚠️ 反向提示词同样建议使用英文
- ⚠️ 不要过度使用，可能影响生成效果
- ⚠️ 可以保存常用的反向提示词模板

#### 相关术语
- 提示词 (Prompt)

---

### 4. 模型 (Model)

#### 功能描述
AI 用来生成图片的"知识"文件。不同的模型就像不同风格的画家，有的擅长写实，有的擅长动漫，有的擅长风景。

#### 使用场景
| 模型类型 | 适用场景 |
|---------|---------|
| 写实模型 | 生成逼真的照片风格图片 |
| 动漫模型 | 生成动漫、二次元风格图片 |
| 艺术模型 | 生成油画、水彩等艺术风格图片 |
| 通用模型 | 适合多种风格的通用模型 |

#### 参数说明
| 参数 | 说明 |
|-----|------|
| 模型名称 | 模型的标识名称 |
| 模型类型 | SD1.5、SDXL、SD2.1 等 |
| 文件大小 | 通常 2GB-6GB |
| 文件格式 | .safetensors 或 .ckpt |

#### 示例

> ⚠️ **时效性提示：** 以下内容可能随软件版本更新而变化，请以官方最新文档为准。

```
常用模型：
- realisticVision：写实风格
- anything-v5：动漫风格
- dreamshaper：通用风格
- sdxl-base：SDXL 高质量模型
```

#### 注意事项
- ⚠️ 不同模型需要不同的配置参数
- ⚠️ 模型文件较大，下载需要时间
- ⚠️ 建议从 Civitai 等可信平台下载模型
- ⚠️ 注意模型的授权协议

#### 相关术语
- Checkpoint
- LoRA
- VAE

---

### 5. 工作流 (Workflow)

#### 功能描述
一系列节点连接起来的操作流程。就像一条流水线，每个节点完成一个任务，最终生成你想要的结果。

#### 使用场景
- 保存常用的生成流程
- 分享给他人使用
- 复杂的图像处理任务

#### 参数说明
| 参数 | 说明 |
|-----|------|
| 节点连接 | 节点之间的数据流向 |
| 参数设置 | 每个节点的具体参数 |
| 文件格式 | .json 格式保存 |

#### 示例
```
简单文生图工作流：
Load Checkpoint → CLIP Text Encode (Prompt) → KSampler → VAE Decode → Save Image
```

#### 注意事项
- ⚠️ 工作流需要对应的模型和插件才能运行
- ⚠️ 可以导入他人分享的工作流
- ⚠️ 建议保存常用工作流以便复用

#### 相关术语
- 节点 (Node)
- ComfyUI

---

### 6. 节点 (Node)

#### 功能描述
工作流中的一个功能单元，比如"加载模型"、"输入提示词"、"生成图片"等。每个节点就像一个工具，完成特定的任务。

#### 使用场景
| 节点类型 | 功能 |
|---------|------|
| 输入节点 | 加载模型、输入图片、输入文字 |
| 处理节点 | 调整大小、预处理、编码 |
| 生成节点 | KSampler（核心生成节点）|
| 输出节点 | 保存图片、预览图片 |

#### 参数说明
每个节点有不同的参数，常见参数包括：
- 输入端口：接收数据的接口
- 输出端口：输出数据的接口
- 参数设置：节点的具体配置

#### 示例
```
常用节点：
- Load Checkpoint：加载模型
- CLIP Text Encode：编码提示词
- KSampler：核心采样器
- VAE Decode：解码潜空间
- Save Image：保存图片
```

#### 注意事项
- ⚠️ 节点之间的连接要正确
- ⚠️ 可以通过右键菜单添加节点
- ⚠️ 双击节点可以折叠/展开

#### 相关术语
- 工作流 (Workflow)

---

### 7. 采样器 (Sampler)

#### 功能描述
AI 生成图片时使用的算法。不同的采样器就像不同的绘画技法，会影响生成速度、质量和风格。

#### 使用场景
| 采样器 | 特点 | 适用场景 |
|-------|------|---------|
| Euler a | 速度快，效果好 | 日常使用 |
| DPM++ 2M Karras | 质量高，细节好 | 高质量生成 |
| DDIM | 稳定，可复现 | 需要精确控制 |
| UniPC | 速度快，质量好 | 快速生成 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 采样器名称 | 选择不同的采样算法 | Euler a 或 DPM++ 2M |
| 调度器 | 控制采样过程 | normal 或 karras |

#### 示例
```
推荐组合：
- 日常使用：Euler a + 20-30 步
- 高质量：DPM++ 2M Karras + 25-40 步
- 快速预览：UniPC + 15-20 步
```

#### 注意事项
- ⚠️ 不同采样器适合不同的步数
- ⚠️ Karras 调度器通常效果更好
- ⚠️ 建议尝试不同采样器找到最适合的

#### 相关术语
- 步数 (Steps)
- KSampler

---

### 8. 步数 (Steps)

#### 功能描述
AI 生成图片时的迭代次数。步数越多，AI 会更精细地处理图片，但生成时间也会更长。

#### 使用场景
| 步数范围 | 效果 | 适用场景 |
|---------|------|---------|
| 10-15 步 | 快速，质量一般 | 快速预览 |
| 20-30 步 | 平衡速度和质量 | 日常使用 |
| 30-50 步 | 高质量，细节丰富 | 最终输出 |
| 50+ 步 | 质量提升有限 | 特殊需求 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 步数值 | 迭代次数 | 20-30 |

#### 示例
```
步数对比：
- 15 步：快速生成，适合测试提示词
- 25 步：平衡选择，适合日常使用
- 40 步：高质量，适合最终输出
```

#### 注意事项
- ⚠️ 步数过多不一定效果更好，可能反而变差
- ⚠️ 不同采样器适合的步数不同
- ⚠️ 建议先用低步数测试，满意后再提高

#### 相关术语
- 采样器 (Sampler)

---

### 9. 分辨率 (Resolution)

#### 功能描述
图片的大小，用宽度和高度的像素值表示，如 512×512、1024×1024。分辨率越高，图片越大，细节越多，但需要的显存也越多。

#### 使用场景
| 分辨率 | 特点 | 适用场景 |
|-------|------|---------|
| 512×512 | 生成快，显存需求低 | 快速测试 |
| 768×768 | 平衡选择 | 日常使用 |
| 1024×1024 | 高质量 | 最终输出 |
| 1024×1536 | 竖版构图 | 人像、海报 |
| 1536×1024 | 横版构图 | 风景、宽屏 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 宽度 | 图片宽度像素 | 512 或 1024 |
| 高度 | 图片高度像素 | 512 或 1024 |

#### 示例
```
常用分辨率：
- 正方形：512×512、1024×1024
- 竖版：512×768、1024×1536
- 横版：768×512、1536×1024
```

#### 注意事项
- ⚠️ 分辨率需要是 8 的倍数
- ⚠️ 分辨率越高，需要显存越多
- ⚠️ 不同模型有最佳分辨率，如 SDXL 推荐 1024×1024
- ⚠️ 可以先生成小图，再用高清修复放大

#### 相关术语
- 高清修复 (Upscale)
- 显存 (VRAM)

## 二、模型相关术语

### 1. Checkpoint

#### 功能描述
完整的 AI 模型文件，决定图片的整体风格。Checkpoint 就像一个完整的"画家"，包含了生成图片所需的所有知识。

#### 使用场景
- 作为生成图片的基础模型
- 决定图片的整体风格
- 加载到工作流的起点

#### 参数说明
| 参数 | 说明 |
|-----|------|
| 文件格式 | .safetensors（推荐）或 .ckpt |
| 文件大小 | 通常 2GB-6GB |
| 模型版本 | SD1.5、SDXL、SD2.1 等 |

#### 示例
```
常用 Checkpoint：
- realisticVision_v51：写实风格
- dreamshaper_8：通用风格
- anything-v5：动漫风格
- sdxl_base_1.0：SDXL 基础模型
```

#### 注意事项
- ⚠️ Checkpoint 文件较大，注意存储空间
- ⚠️ 建议使用 .safetensors 格式，更安全
- ⚠️ 不同 Checkpoint 可能需要不同的 VAE
- ⚠️ 下载时注意模型的版本和兼容性

#### 相关术语
- 模型 (Model)
- VAE
- LoRA

---

### 2. LoRA (Low-Rank Adaptation)

#### 功能描述
小型模型，可以给图片添加特定风格或特征。LoRA 就像一个"风格滤镜"，可以给基础模型添加特定的风格、人物或元素。

#### 使用场景
| LoRA 类型 | 用途 |
|----------|------|
| 风格 LoRA | 添加特定艺术风格 |
| 人物 LoRA | 生成特定人物形象 |
| 概念 LoRA | 添加特定元素或概念 |
| 服装 LoRA | 添加特定服装风格 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 权重 (Weight) | LoRA 的影响强度 | 0.5-1.0 |
| 触发词 | 激活 LoRA 的关键词 | 在提示词中添加 |

#### 示例
```
使用 LoRA：
1. 加载基础 Checkpoint（如 realisticVision）
2. 加载 LoRA（如 anime_style LoRA）
3. 设置权重（如 0.7）
4. 在提示词中添加触发词
```

#### 注意事项
- ⚠️ 权重过高可能导致图片变形
- ⚠️ 多个 LoRA 可以叠加使用
- ⚠️ 注意 LoRA 与基础模型的兼容性
- ⚠️ 使用触发词才能发挥 LoRA 效果

#### 相关术语
- Checkpoint
- 权重 (Weight)

---

### 3. ControlNet

#### 功能描述
用来精确控制图片生成的工具。ControlNet 就像一个"骨架"，可以控制人物的姿态、画面的深度、边缘轮廓等。

#### 使用场景
| ControlNet 类型 | 用途 |
|----------------|------|
| OpenPose | 控制人物姿态 |
| Canny | 控制边缘轮廓 |
| Depth | 控制画面深度 |
| Lineart | 控制线稿 |
| Tile | 控制细节纹理 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 控制强度 | ControlNet 的影响程度 | 0.5-1.0 |
| 预处理器 | 对输入图片的预处理方式 | 根据类型选择 |
| 模型 | ControlNet 的模型文件 | 与类型匹配 |

#### 示例
```
使用 OpenPose ControlNet：
1. 加载 OpenPose ControlNet 模型
2. 上传参考图片
3. 预处理器自动检测姿态
4. 生成相同姿态的新图片
```

#### 注意事项
- ⚠️ ControlNet 模型需要与基础模型兼容
- ⚠️ 控制强度要适中，太高可能影响画质
- ⚠️ 预处理器和模型要匹配
- ⚠️ 需要安装 ControlNet 插件

#### 相关术语
- 预处理器 (Preprocessor)
- ControlNet 模型

---

### 4. VAE (Variational Autoencoder)

#### 功能描述
用来优化图片颜色和细节的模型。VAE 就像一个"调色师"，可以让图片的颜色更加鲜艳、细节更加丰富。

#### 使用场景
- 修复图片颜色偏灰的问题
- 提升图片的色彩饱和度
- 改善图片的整体质量

#### 参数说明
| 参数 | 说明 |
|-----|------|
| VAE 名称 | VAE 模型的名称 |
| 来源 | 内置或外部加载 |

#### 示例
```
使用 VAE：
1. 在 Checkpoint Loader 中选择 VAE
2. 或使用独立的 Load VAE 节点
3. 连接到 VAE Decode 节点
```

#### 注意事项
- ⚠️ 有些 Checkpoint 自带 VAE，不需要额外加载
- ⚠️ VAE 不匹配可能导致颜色问题
- ⚠️ 常用 VAE：vae-ft-mse-840000

#### 相关术语
- Checkpoint
- VAE Decode

---

### 5. CLIP

#### 功能描述
用来理解提示词语义的模型。CLIP 就像一个"翻译官"，把你写的文字转换成 AI 能理解的语言。

#### 使用场景
- 编码正向提示词
- 编码反向提示词
- 理解文字描述的含义

#### 参数说明
| 参数 | 说明 |
|-----|------|
| CLIP 模型 | 来自 Checkpoint 或独立加载 |
| Stop at last layers | CLIP 停止层 | 通常为 1 或 2 |

#### 示例
```
CLIP Text Encode 节点：
- 输入：提示词文本
- 输出：CLIP 编码后的条件
- 用于 KSampler 的条件输入
```

#### 注意事项
- ⚠️ CLIP 模型通常包含在 Checkpoint 中
- ⚠️ Stop at last layers 参数影响提示词理解

#### 相关术语
- 提示词 (Prompt)
- CLIP Text Encode

### 6. IP-Adapter

#### 功能描述
可以让 AI 学习参考图片风格的工具。IP-Adapter 就像一个"风格学习器"，可以让 AI 模仿参考图片的风格、构图或内容。

#### 使用场景
| IP-Adapter 类型 | 用途 |
|----------------|------|
| 风格迁移 | 学习参考图片的艺术风格 |
| 构图参考 | 学习参考图片的构图 |
| 内容参考 | 学习参考图片的内容元素 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 权重 | 参考图片的影响强度 | 0.5-1.0 |
| 参考图片 | 用于学习的源图片 | 清晰图片效果更好 |

#### 示例
```
使用 IP-Adapter：
1. 加载 IP-Adapter 模型
2. 上传参考图片
3. 设置权重
4. 生成带有参考风格的图片
```

#### 注意事项
- ⚠️ 需要安装 IP-Adapter 插件
- ⚠️ 权重过高可能导致过度模仿
- ⚠️ 参考图片质量影响最终效果

#### 相关术语
- 风格迁移
- ControlNet

---

### 7. InstantID

#### 功能描述
用来保持人脸一致性的工具。InstantID 就像一个"人脸复制器"，可以让生成的人物保持相同的面部特征。

#### 使用场景
- 生成同一个人的不同照片
- 创建角色系列图
- 保持人物形象一致

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 参考照片 | 提供人脸特征的源图片 | 清晰正面照 |
| 影响强度 | 人脸特征的保留程度 | 0.8-1.0 |

#### 示例
```
使用 InstantID：
1. 加载 InstantID 模型
2. 上传清晰的正面照片
3. 设置影响强度
4. 生成保持人脸一致的新图片
```

#### 注意事项
- ⚠️ 需要安装 InstantID 插件
- ⚠️ 参考照片要清晰、正面
- ⚠️ 影响强度太高可能导致表情僵硬

#### 相关术语
- 人脸控制
- ControlNet

## 三、工作流相关术语

### 1. 文生图 (Text-to-Image)

#### 功能描述
从文字描述生成图片。这是最基础的 AI 图像生成方式。

#### 使用场景
- 根据创意描述生成图片
- 快速可视化想法
- 生成各种风格的图片

#### 示例
```
基本流程：
Load Checkpoint → CLIP Text Encode (Prompt) → KSampler → VAE Decode → Save Image
```

#### 相关术语
- 提示词 (Prompt)
- KSampler

---

### 2. 图生图 (Image-to-Image)

#### 功能描述
从一张图片生成另一张图片。可以保持原图的构图，改变风格或内容。

#### 使用场景
- 风格转换
- 图片优化
- 草图上色

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| 降噪强度 (Denoise) | 对原图的修改程度 | 0.3-0.7 |

#### 示例
```
基本流程：
Load Checkpoint → Load Image → CLIP Text Encode → KSampler (with image input) → VAE Decode → Save Image
```

#### 注意事项
- ⚠️ 降噪强度决定修改程度
- ⚠️ 值为 1 时相当于完全重绘

### 7. 降噪强度 (Denoising Strength)

#### 功能描述
图生图时 AI 对原图的修改程度。值越大，AI 对原图的改变越大。

#### 使用场景
| 降噪强度 | 效果 |
|---------|------|
| 0.1-0.3 | 轻微修改，保留原图大部分内容 |
| 0.4-0.6 | 中等修改，风格改变但构图保留 |
| 0.7-0.9 | 较大修改，只保留基本构图 |
| 1.0 | 完全重绘 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| Denoise | 降噪强度值 | 0.3-0.7 |

#### 示例
```
场景示例：
- 风格转换：0.5-0.7
- 细节优化：0.3-0.4
- 草图上色：0.6-0.8
```

#### 注意事项
- ⚠️ 值为 0 时完全不修改
- ⚠️ 值为 1 时相当于文生图

#### 相关术语
- 图生图 (Image-to-Image)

## 四、参数相关术语

### 1. CFG Scale (Classifier Free Guidance Scale)

#### 功能描述
提示词的影响强度。值越大，AI 越严格地按照提示词生成；值越小，AI 有更多自由发挥空间。

#### 使用场景
| CFG 值 | 效果 |
|-------|------|
| 1-4 | AI 自由发挥，可能偏离提示词 |
| 5-8 | 平衡选择，适合大多数情况 |
| 9-15 | 严格遵循提示词，可能过度饱和 |
| 15+ | 可能导致颜色异常 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| CFG Scale | 提示词影响强度 | 7-8 |

#### 示例
```
推荐设置：
- 日常使用：7
- 需要精确控制：8-10
- 创意探索：5-6
```

#### 注意事项
- ⚠️ CFG 过高可能导致颜色过度饱和
- ⚠️ CFG 过低可能偏离提示词
- ⚠️ 不同模型适合的 CFG 不同

#### 相关术语
- 提示词 (Prompt)

---

### 2. Seed (随机种子)

#### 功能描述
随机种子，用于控制生成结果的随机性。相同的种子和参数会生成相同的图片。

#### 使用场景
| Seed 值 | 效果 |
|--------|------|
| -1 | 每次随机生成不同的图片 |
| 固定值 | 每次生成相同的图片 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| Seed | 随机种子值 | -1 或任意整数 |

#### 示例
```
使用场景：
- 探索不同效果：使用 -1
- 复现结果：记录并使用固定种子
- 微调图片：固定种子后调整其他参数
```

#### 注意事项
- ⚠️ 固定种子可以复现结果
- ⚠️ 其他参数改变时，相同种子结果也会改变

#### 相关术语
- KSampler

---

### 3. Batch Size (批量大小)

#### 功能描述
一次生成的图片数量。批量越大，一次生成的图片越多，但需要更多显存。

#### 使用场景
| Batch Size | 效果 |
|-----------|------|
| 1 | 单张生成，显存需求低 |
| 2-4 | 少量批量，适合对比 |
| 4-8 | 中等批量，效率高 |
| 8+ | 大批量，需要大显存 |

#### 参数说明
| 参数 | 说明 | 建议值 |
|-----|------|-------|
| Batch Size | 每批生成的数量 | 1-4 |

#### 示例
```
显存参考：
- 4GB 显存：Batch Size 1
- 8GB 显存：Batch Size 2-4
- 12GB+ 显存：Batch Size 4-8
```

#### 注意事项
- ⚠️ 批量大小影响显存需求
- ⚠️ 批量过大可能导致显存不足

#### 相关术语
- 显存 (VRAM)

---

### 4. Weight (权重)

#### 功能描述
调整提示词中某些词的重要性。权重越高，该词对生成结果的影响越大。

#### 使用场景
- 强调提示词中的关键元素
- 弱化某些元素的影响
- 精细控制生成结果

#### 参数说明
| 语法 | 说明 | 示例 |
|-----|------|------|
| (word) | 增加 1.1 倍权重 | (cat) |
| (word:1.2) | 指定权重倍数 | (cat:1.2) |
| [word] | 减少 0.9 倍权重 | [cat] |

#### 示例
```
权重示例：
- a (cute) cat：强调 cute
- a (cat:1.5)：强调 cat
- a [dog] and cat：弱化 dog
```

#### 注意事项
- ⚠️ 权重过高可能导致图片变形
- ⚠️ 权重可以为负数，效果类似反向提示词

#### 相关术语
- 提示词 (Prompt)
