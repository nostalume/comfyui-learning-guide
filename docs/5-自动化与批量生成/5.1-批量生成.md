# 5.1 批量生成

> **文档版本：** 2026.04
> **相关官方文档：** [ComfyUI 官方文档](https://docs.comfy.org/) | [中文文档](https://docs.comfy.org/zh/)

---

## 功能描述

批量生成是指一次性提交多个生成任务，让 ComfyUI 自动连续处理，无需手动逐个操作。这就像是一条"生产线"——你把原材料（提示词、参数）准备好，机器会自动批量生产出多张图片。

### 批量生成原理

ComfyUI 的批量生成主要依赖以下机制：

1. **Batch Size 机制**：在同一个推理过程中同时处理多个样本，共享模型加载和预处理开销
2. **队列系统**：将多个任务按顺序排队，依次执行
3. **参数迭代**：通过脚本或节点自动遍历不同的参数组合

---

## 使用场景

| 场景 | 推荐方式 | 说明 |
|------|----------|------|
| 快速生成多张相似图片 | Batch Size | 一次生成多张，适合挑选最佳结果 |
| 测试不同种子效果 | 种子批量 | 固定提示词，变化种子 |
| 对比不同提示词效果 | 提示词矩阵 | 自动组合多个提示词变体 |
| 测试不同 LoRA 风格 | LoRA 批量切换 | 同一提示词，不同 LoRA |
| 大规模图片生产 | API 批量调用 | 配合脚本自动化处理 |

## 5.1.1 内置批量生成

### 方法一：Batch Size 方式

#### 功能描述

在 空Latent图像（Empty Latent Image）节点中设置 batch_size 参数，让模型在一次推理中同时生成多张图片。这些图片共享相同的提示词和参数，但使用不同的随机噪声初始化。

#### 参数说明

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| batch_size | 整数 | 1 | 同时生成的图片数量 |
| width | 整数 | 512 | 图片宽度 |
| height | 整数 | 512 | 图片高度 |

#### 操作步骤

1. 在工作流中找到 **Empty Latent Image** 节点
2. 将 **batch_size** 参数从默认值 1 改为所需数量（如 4）
3. 点击 **Queue Prompt** 执行
4. 在预览区域查看生成的多张图片

#### 示例

```
设置 batch_size = 4：
├── 生成图片 1（种子：随机）
├── 生成图片 2（种子：随机）
├── 生成图片 3（种子：随机）
└── 生成图片 4（种子：随机）
```

#### 注意事项

- ⚠️ **显存占用**：batch_size 增大会显著增加显存占用。建议根据显卡显存调整：
  - 4GB 显存：batch_size ≤ 2
  - 8GB 显存：batch_size ≤ 4
  - 12GB+ 显存：batch_size 可设为 8 或更高
- 💡 **性能提示**：batch_size 方式比多次单独生成更高效，因为模型只需加载一次
- 💡 **图片差异**：虽然参数相同，但由于随机噪声不同，每张图片会有明显差异

### 方法二：种子批量

#### 功能描述

通过队列系统自动执行多次生成，每次使用不同的随机种子。适合需要大量图片进行筛选的场景。

#### 操作步骤

1. 找到 **K采样器（KSampler）** 节点中的 **seed** 参数
2. **取消勾选** "control_after_generate" 或确保种子设为随机
3. 点击 **Queue Prompt** 旁边的数字输入框
4. 输入想要生成的数量（如 10）
5. 点击确认，系统会自动添加 10 个任务到队列

#### 示例

```
设置生成数量为 5：
├── 任务 1：seed = 12345（随机）
├── 任务 2：seed = 67890（随机）
├── 任务 3：seed = 11111（随机）
├── 任务 4：seed = 22222（随机）
└── 任务 5：seed = 33333（随机）
```

#### 注意事项

- 💡 与 Batch Size 不同，种子批量是多次独立推理，每张图片单独生成
- 💡 可以配合固定种子使用，只需在 KSampler 中取消 "randomize" 选项

## 5.1.2 提示词矩阵

### 功能描述

使用特殊的语法格式，让 ComfyUI 自动组合生成多个提示词变体。这是测试不同描述词效果的最佳方式。

### 语法说明

| 语法 | 功能 | 示例 |
|------|------|------|
| `{A\|B}` | 随机选择 | `{day\|night}` → 随机选 day 或 night |
| `{A\|B\|C}` | 多选一 | `{red\|blue\|green}` → 随机选一种颜色 |

### 操作步骤

1. 在提示词节点（CLIP Text Encode）中输入提示词
2. 使用 `{选项1|选项2}` 语法标记需要变化的部分
3. 点击 Queue Prompt 执行

### 示例

```
原始提示词：
a {cat|dog|bird} sitting on a {chair|sofa|bed}

可能生成的组合：
├── a cat sitting on a chair
├── a dog sitting on a sofa
├── a bird sitting on a bed
└── ...（每次随机组合）
```

### 注意事项

- 💡 需要安装支持动态提示词的插件（如 Dynamic Prompts）
- 💡 每次执行只会生成一个随机组合，如需所有组合需配合批量功能

## 5.1.3 LoRA 批量切换

### 功能描述

通过构建多个并行分支，每个分支使用不同的 LoRA 模型，一次性生成多种风格的图片。

### 工作流结构

```
Load Checkpoint（基础模型）
        │
        ├── LoRA Loader (风格 A) ──→ KSampler 1 ──→ 图片 A
        │
        ├── LoRA Loader (风格 B) ──→ KSampler 2 ──→ 图片 B
        │
        └── LoRA Loader (风格 C) ──→ KSampler 3 ──→ 图片 C
```

### 操作步骤

1. 加载基础模型（Load Checkpoint 节点）
2. 添加多个 **LoRA Loader** 节点，分别加载不同的 LoRA
3. 每个 LoRA 输出连接到独立的 **KSampler** 节点
4. 各 KSampler 共享相同的提示词输入
5. 执行工作流，同时生成多张不同风格的图片

### 示例配置

| 分支 | LoRA 模型 | 风格描述 |
|------|-----------|----------|
| 分支 1 | anime_style.safetensors | 动漫风格 |
| 分支 2 | realistic_vision.safetensors | 写实风格 |
| 分支 3 | oil_painting.safetensors | 油画风格 |

### 注意事项

- ⚠️ **显存占用**：每个分支都会占用额外显存，注意控制分支数量
- 💡 **效率提示**：这种方式比分别运行多次工作流更高效

## 5.1.4 参数外部化

### 功能描述

将工作流中的关键参数提取为外部输入节点，方便批量修改和管理。这就像给工作流装上了"控制面板"，不用深入内部就能调整参数。

### 参数说明

| Primitive 类型 | 用途 | 常见连接目标 |
|----------------|------|--------------|
| String | 文本输入 | 提示词、负向提示词 |
| Int | 整数参数 | 种子、步数、图片尺寸 |
| Float | 浮点参数 | CFG、LoRA 强度 |
| Boolean | 开关参数 | 某些节点的启用/禁用 |

### 操作步骤

1. 右键点击节点的输入端口（如 K采样器（KSampler） 的 seed 输入）
2. 选择 **Convert to Input**（转换为输入）
3. 在空白处右键，添加 **Primitive** 节点
4. 将 Primitive 节点连接到转换后的输入端口
5. 重复以上步骤，为其他参数创建外部输入

### 示例工作流结构

```
外部参数节点：
├── Primitive (正向提示词) ──→ CLIP文本编码器（CLIP Text Encoder）(positive)
├── Primitive (负向提示词) ──→ CLIP文本编码器（CLIP Text Encoder）(negative)
├── Primitive (种子) ──→ K采样器（KSampler）(seed)
├── Primitive (步数) ──→ K采样器（KSampler）(steps)
└── Primitive (LoRA 强度) ──→ 加载LoRA（Load LoRA）(strength)
```

### 注意事项

- 💡 参数外部化后，工作流更易于复用和分享
- 💡 可以配合 API 调用，实现参数的动态注入

## 常见问题

### Q1：Batch Size 设置多大合适？

**A：** 取决于你的显卡显存大小：

| 显存大小 | 推荐 Batch Size |
|----------|-----------------|
| 4GB | 1-2 |
| 6GB | 2-3 |
| 8GB | 3-4 |
| 12GB | 4-8 |
| 16GB+ | 8-16 |

如果出现显存不足错误（CUDA out of memory），请减小 batch_size。

---

### Q2：批量生成时如何保证图片质量一致？

**A：** 
- 固定种子：取消 KSampler 中的 randomize 选项
- 使用 Batch Size 方式而非多次单独生成
- 确保所有生成任务使用相同的模型和参数

---

### Q3：如何在批量生成中使用不同的提示词？

**A：** 有几种方法：
1. 使用提示词矩阵语法 `{A|B|C}`
2. 配合 API 调用，脚本动态修改提示词
3. 使用 ComfyUI-Impact-Pack 等插件的批量功能

---

### Q4：批量生成中途崩溃怎么办？

**A：**
1. 检查历史记录（按 H 键），找到已完成任务
2. 记录已完成的种子编号
3. 从断点继续设置剩余任务
4. 考虑减小 batch_size 或降低图片分辨率

---

### Q5：批量生成速度太慢怎么办？

**A：** 优化建议：
- 使用 Batch Size 方式代替多次单独生成
- 降低采样步数（steps）
- 使用更快的采样器（如 euler_ancestral、dpmpp_sde）
- 考虑使用 xformers 或 --xformers 启动参数优化显存
