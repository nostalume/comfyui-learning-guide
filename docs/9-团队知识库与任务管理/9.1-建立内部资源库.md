## 概述

### 什么是内部资源库？

**内部资源库**是团队统一管理 ComfyUI 相关资源的中心化存储系统。它包含模型文件、自定义节点、工作流模板、配置文件等所有团队共享的资源。

**核心作用：**
- 📁 **统一存储**：避免资源分散，减少重复下载
- 🔄 **版本管理**：追踪资源变更，支持回滚
- 👥 **团队协作**：多人共享，权限控制
- 📊 **资源追踪**：清晰了解资源使用情况

### 为什么需要建立内部资源库？

| 问题场景 | 无资源库 | 有资源库 |
|---------|---------|---------|
| 新成员入职 | 需要逐个下载模型，耗时数小时 | 直接挂载共享目录，立即可用 |
| 模型版本混乱 | 每人使用不同版本，结果不一致 | 统一版本，结果可复现 |
| 存储空间浪费 | 同一模型多人重复下载 | 一次下载，全员共享 |
| 资源丢失风险 | 个人电脑故障导致资源丢失 | 集中备份，安全可靠 |

```
ComfyUI/
├── models/                          # 模型资源目录
│   ├── checkpoints/                 # 大模型（主模型）
│   │   ├── sd15/                    # Stable Diffusion 1.5 模型
│   │   │   ├── realistic_vision_v5.safetensors
│   │   │   └── realistic_vision_v5.json  # 元数据文件
│   │   ├── sdxl/                    # SDXL 模型
│   │   └── flux/                    # Flux 模型
│   ├── lora/                        # LoRA 微调模型
│   │   ├── style/                   # 风格类 LoRA
│   │   ├── character/               # 角色类 LoRA
│   │   └── concept/                 # 概念类 LoRA
│   ├── controlnet/                  # ControlNet 控制模型
│   │   ├── sd15/                    # SD 1.5 版本
│   │   └── sdxl/                    # SDXL 版本
│   ├── ipadapter/                   # IP-Adapter 模型
│   ├── vae/                         # VAE 编解码模型
│   ├── clip/                        # CLIP 文本编码模型
│   ├── embeddings/                  # Textual Inversion 嵌入
│   └── upscale_models/              # 放大模型
├── custom_nodes/                    # 自定义节点目录
├── input/                           # 输入文件目录
├── output/                          # 输出文件目录
└── workflows/                       # 工作流模板目录
    ├── txt2img/                     # 文生图模板
    ├── img2img/                     # 图生图模板
    ├── controlnet/                  # ControlNet 模板
    └── video/                       # 视频生成模板
```

### 各目录功能说明

| 目录 | 功能描述 | 使用场景 | 注意事项 |
|-----|---------|---------|---------|
| `checkpoints/` | 存放主模型文件 | 生成图像的基础模型 | 文件较大（2-6GB），注意存储空间 |
| `lora/` | 存放 LoRA 微调模型 | 风格迁移、角色一致性 | 需配合主模型使用 |
| `controlnet/` | 存放控制模型 | 精确控制生成结果 | 注意与主模型版本匹配 |
| `vae/` | 存放 VAE 模型 | 改善色彩和细节 | 部分主模型已内置 VAE |
| `workflows/` | 存放工作流模板 | 快速复用配置 | 建议按场景分类 |

## 模型资源管理

### 模型命名规范

#### 功能描述
统一的命名规范可以帮助团队成员快速识别模型类型、版本和用途，避免混淆。

#### 命名格式

```
[基础模型]_[风格/用途]_[版本]_[作者].safetensors
```

#### 参数详解

| 参数 | 说明 | 示例值 |
|-----|------|-------|
| 基础模型 | 模型的基础架构 | sd15, sdxl, flux |
| 风格/用途 | 模型的主要风格或用途 | realistic, anime, portrait |
| 版本 | 模型版本号 | v5, v1.0, 20240807 |
| 作者 | 模型作者或来源 | sg, author, official |

#### 命名示例

```
✅ 正确示例：
sd15_realistic_vision_v5_sg.safetensors    # SD1.5写实模型，v5版本，作者SG
sdxl_juggernaut_xl_v9_rd.safetensors       # SDXL模型，v9版本，作者RD
flux_dev_20240807_official.safetensors     # Flux开发版，官方发布
lora_anime_style_v1_custom.safetensors     # 动漫风格LoRA，v1版本
controlnet_depth_sd15_v1.safetensors       # 深度ControlNet，SD1.5版本

❌ 错误示例：
realistic_vision.safetensors               # 缺少基础模型标识
model (1).safetensors                      # 使用默认下载名称
新模型.safetensors                          # 使用中文命名
```

#### 注意事项

1. **使用英文命名**：避免使用中文或特殊字符
2. **保持简洁**：名称不宜过长，控制在50字符内
3. **版本号格式**：建议使用 v1, v2 或日期格式
4. **区分大小写**：建议统一使用小写字母和下划线

## 资源共享方案

### 方案对比

| 方案 | 适用场景 | 优点 | 缺点 | 实施难度 |
|-----|---------|------|------|---------|
| 网络共享 | 小型团队，局域网环境 | 简单易用，成本低 | 依赖网络稳定性 | ⭐ 简单 |
| Git版本控制 | 中型团队，需要版本管理 | 版本追踪，协作方便 | 不适合大文件 | ⭐⭐ 中等 |
| 私有仓库 | 大型团队，有安全需求 | 完全控制，安全性高 | 需要技术支持 | ⭐⭐⭐ 复杂 |

### 方案一：网络共享（推荐小型团队）

#### 功能描述
通过网络共享目录，让团队成员直接访问共享资源。

#### Windows 设置步骤

**步骤1：创建共享目录**

```powershell
# 在服务器上创建共享目录
New-Item -Path "D:\ComfyUI_Resources" -ItemType Directory

# 设置共享权限
net share comfyui_resources=D:\ComfyUI_Resources /grant:everyone,full
```

**步骤2：客户端映射网络驱动器**

```powershell
# 映射网络驱动器到 Z 盘
net use Z: \\server\comfyui_resources /persistent:yes

# 验证连接
dir Z:\
```

**步骤3：配置 ComfyUI 使用共享目录**

修改 ComfyUI 启动参数：

```bash
# Windows
python main.py --input-directory "Z:\input" --output-directory "Z:\output"

# 或创建符号链接
mklink /D "ComfyUI\models" "Z:\models"
```

#### Linux 设置步骤

```bash
# 服务器端：安装 NFS 服务
sudo apt install nfs-kernel-server

# 配置共享目录
echo "/data/comfyui_resources *(rw,sync,no_subtree_check)" >> /etc/exports

# 重启 NFS 服务
sudo systemctl restart nfs-kernel-server

# 客户端：挂载共享目录
sudo mkdir -p /mnt/comfyui
sudo mount -t nfs server:/data/comfyui_resources /mnt/comfyui

# 设置开机自动挂载
echo "server:/data/comfyui_resources /mnt/comfyui nfs defaults 0 0" >> /etc/fstab
```

### 方案三：私有模型仓库（推荐大型团队）

#### 使用 MinIO 搭建对象存储

**步骤1：安装 MinIO**

```bash
# Docker 方式安装
docker run -d \
  --name minio \
  -p 9000:9000 \
  -p 9001:9001 \
  -v /data/minio:/data \
  -e MINIO_ROOT_USER=admin \
  -e MINIO_ROOT_PASSWORD=your_password \
  minio/minio server /data --console-address ":9001"
```

**步骤2：创建存储桶**

```bash
# 使用 MinIO Client (mc)
mc alias set myminio http://localhost:9000 admin your_password

# 创建存储桶
mc mb myminio/comfyui-models
mc mb myminio/comfyui-workflows
```

**步骤3：上传资源**

```bash
# 上传模型
mc cp --recursive models/checkpoints/ myminio/comfyui-models/checkpoints/

# 上传工作流
mc cp --recursive workflows/ myminio/comfyui-workflows/
```

## 资源备份策略

### 备份策略详解

#### 功能描述
定期备份重要资源，防止数据丢失，支持快速恢复。

#### 备份范围

| 类型 | 重要程度 | 备份频率 | 保留期限 | 存储位置 |
|-----|---------|---------|---------|---------|
| 模型元数据 | ⭐⭐⭐ 高 | 每天 | 永久 | Git 仓库 |
| 工作流模板 | ⭐⭐⭐ 高 | 每天 | 永久 | Git 仓库 |
| 配置文件 | ⭐⭐⭐ 高 | 每天 | 永久 | Git 仓库 |
| 模型文件 | ⭐⭐ 中 | 每周 | 3 个月 | 异地备份 |
| 输出文件 | ⭐ 低 | 按需 | 30 天 | 本地备份 |

### 自动备份脚本

#### Windows 备份脚本

```powershell
# backup_resources.ps1

# 配置
$Date = Get-Date -Format "yyyyMMdd"
$BackupDir = "D:\Backups\comfyui_$Date"
$ComfyUIDir = "D:\ComfyUI"

# 创建备份目录
New-Item -Path $BackupDir -ItemType Directory -Force

# 备份模型元数据
Write-Host "备份模型元数据..."
Copy-Item -Path "$ComfyUIDir\models\*.json" -Destination "$BackupDir\models\" -Recurse -Force

# 备份工作流
Write-Host "备份工作流..."
Copy-Item -Path "$ComfyUIDir\workflows" -Destination "$BackupDir\" -Recurse -Force

# 备份配置
Write-Host "备份配置..."
Copy-Item -Path "$ComfyUIDir\custom_nodes\README.md" -Destination "$BackupDir\custom_nodes\" -Force
Copy-Item -Path "$ComfyUIDir\custom_nodes\requirements.txt" -Destination "$BackupDir\custom_nodes\" -Force

# 清理旧备份（保留最近7个）
$OldBackups = Get-ChildItem "D:\Backups" | Sort-Object CreationTime -Descending | Select-Object -Skip 7
foreach ($Backup in $OldBackups) {
    Remove-Item $Backup.FullName -Recurse -Force
    Write-Host "已删除旧备份: $($Backup.Name)"
}

Write-Host "✅ 备份完成: $BackupDir"
```

#### Linux 备份脚本

```bash
#!/bin/bash
# backup_resources.sh

DATE=$(date +%Y%m%d)
BACKUP_DIR="/backup/comfyui_$DATE"

# 备份配置

cp $COMFYUI_DIR/custom_nodes/requirements.txt $BACKUP_DIR/custom_nodes/

# 清理旧备份（保留最近7个）

echo "✅ 备份完成: $BACKUP_DIR"
```

### 存储空间监控

#### 监控脚本

```python
# storage_monitor.py

import shutil
import os
import json
from datetime import datetime

def check_storage(path, threshold_gb=10):
    """
    检查存储空间
    
    参数:
        path: 检查路径
        threshold_gb: 警告阈值（GB）
    
    返回:
        dict: 存储信息
    """
    total, used, free = shutil.disk_usage(path)
    
    result = {
        "path": path,
        "total_gb": round(total / (1024**3), 2),
        "used_gb": round(used / (1024**3), 2),
        "free_gb": round(free / (1024**3), 2),
        "used_percent": round(used / total * 100, 1),
        "warning": free / (1024**3) < threshold_gb,
        "check_time": datetime.now().isoformat()
    }
    
    return result

def get_directory_size(path):
    """获取目录大小"""
    total_size = 0
    for dirpath, dirnames, filenames in os.walk(path):
        for f in filenames:
            fp = os.path.join(dirpath, f)
            if not os.path.islink(fp):
                total_size += os.path.getsize(fp)
    return round(total_size / (1024**3), 2)

def generate_report(comfyui_path):
    """生成存储报告"""
    report = {
        "storage": check_storage(comfyui_path),
        "directories": {
            "models": get_directory_size(os.path.join(comfyui_path, "models")),
            "workflows": get_directory_size(os.path.join(comfyui_path, "workflows")),
            "output": get_directory_size(os.path.join(comfyui_path, "output")),
            "input": get_directory_size(os.path.join(comfyui_path, "input"))
        }
    }
    
    return report

if __name__ == "__main__":
    COMFYUI_PATH = "D:/ComfyUI"  # 修改为实际路径
    
    report = generate_report(COMFYUI_PATH)
    
    print("=" * 50)
    print("ComfyUI 存储空间报告")
    print("=" * 50)
    print(f"检查时间: {report['storage']['check_time']}")
    print(f"总空间: {report['storage']['total_gb']} GB")
    print(f"已使用: {report['storage']['used_gb']} GB ({report['storage']['used_percent']}%)")
    print(f"剩余空间: {report['storage']['free_gb']} GB")
    print()
    print("目录大小:")
    for dir_name, size in report['directories'].items():
        print(f"  {dir_name}: {size} GB")
    
    if report['storage']['warning']:
        print()
        print("⚠️ 警告: 剩余空间不足!")
    
    print("=" * 50)
```

## 常见问题 FAQ

### Q1：模型文件太大，存储空间不够怎么办？

**解决方案：**

1. **使用量化模型**
   ```bash
   # 下载 FP16 或 INT8 量化版本
   # 文件大小可减少 50%-75%
   ```

2. **按需下载模型**
   - 只下载当前项目需要的模型
   - 使用后及时清理不常用模型

3. **使用网络存储**
   - 将模型存储在 NAS 或云存储
   - 按需挂载使用

### Q2：团队成员使用不同操作系统，路径问题怎么解决？

**解决方案：**

1. **使用相对路径**
   ```python
   # 推荐
   model_path = os.path.join("models", "checkpoints", "model.safetensors")
   
   # 不推荐
   model_path = "D:\\ComfyUI\\models\\checkpoints\\model.safetensors"
   ```

2. **使用配置文件**
   ```json
   {
       "paths": {
           "models": "${COMFYUI_ROOT}/models",
           "workflows": "${COMFYUI_ROOT}/workflows"
       }
   }
   ```

3. **使用环境变量**
   ```bash
   # Windows
   set COMFYUI_ROOT=D:\ComfyUI
   
   # Linux/macOS
   export COMFYUI_ROOT=/opt/ComfyUI
   ```

### Q3：模型版本更新后，旧工作流不兼容怎么办？

**解决方案：**

1. **保留旧版本模型**
   ```
   models/checkpoints/sd15/
   ├── realistic_vision_v4.safetensors  # 保留旧版本
   └── realistic_vision_v5.safetensors  # 新版本
   ```

2. **工作流指定模型版本**
   - 在工作流元数据中明确指定模型版本
   - 不同版本使用不同文件名

3. **版本兼容性测试**
   - 更新模型前先测试兼容性
   - 记录不兼容的工作流

### Q4：如何快速找到需要的模型？

**解决方案：**

1. **使用标签系统**
   ```json
   {
       "tags": ["realistic", "portrait", "photography", "indoor"]
   }
   ```

2. **维护索引文档**
   - 定期更新模型清单
   - 按风格、用途分类

3. **使用搜索工具**
   ```bash
   # 搜索包含特定标签的模型
   grep -r "portrait" models/*.json
   ```
