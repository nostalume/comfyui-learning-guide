## 概述

### 什么是优化策略？

优化策略是指通过各种技术手段，提升 ComfyUI 的生成效率、降低资源占用、改善用户体验的方法集合。

### 优化的目标

| 目标 | 说明 |
|-----|------|
| **提升速度** | 减少生成时间 |
| **降低显存** | 支持更大模型或分辨率 |
| **提高质量** | 保持或提升生成质量 |
| **稳定运行** | 减少 OOM 和崩溃 |

### 优化策略分类

| 类别 | 策略 | 效果 |
|-----|------|------|
| **精度优化** | FP16/BF16/FP8 | 显存减半，速度提升 |
| **内存优化** | 模型分块、卸载 | 支持低显存运行 |
| **计算优化** | xFormers、SDPA | 速度提升 20-30% |
| **采样优化** | 采样器选择、步数调整 | 速度提升 30-50% |
| **批量优化** | 批量大小调整 | 提高吞吐量 |

### 本章你将学到什么？

1. 精度量化的配置方法
2. 模型分块加载的使用
3. 采样参数的优化技巧
4. 批量处理的最佳实践
5. 综合优化配置方案

## 精度量化

### 什么是精度量化？

精度量化是指降低模型参数的数值精度，从 FP32（32位浮点）降低到 FP16（16位浮点）或更低，以减少显存占用和加速计算。

### 精度类型对比

| 精度 | 位数 | 显存占用 | 速度 | 质量 | 支持范围 |
|-----|------|---------|------|------|---------|
| FP32 | 32位 | 100% | 基准 | 最高 | 所有 GPU |
| FP16 | 16位 | 50% | +30% | 几乎无损 | 所有 GPU |
| BF16 | 16位 | 50% | +30% | 更稳定 | RTX 30/40+ |
| FP8 | 8位 | 25% | +20% | 轻微损失 | RTX 40+ |
| INT8 | 8位 | 25% | +30% | 有损失 | 需要量化 |

### FP16（半精度）

#### 功能描述

FP16 是最常用的量化方案，将模型从 FP32 转换为 FP16。

#### 使用场景

- 所有 NVIDIA GPU 都支持
- 需要减少显存占用
- 希望加速生成

#### 启用方法

```bash
python main.py --fp16-unet --fp16-vae
```

#### 参数详解

| 参数 | 说明 | 推荐值 |
|-----|------|-------|
| `--fp16-unet` | U-Net 使用 FP16 | 推荐启用 |
| `--fp16-vae` | VAE 使用 FP16 | 推荐启用 |
| `--fp16-text-enc` | 文本编码器使用 FP16 | 可选 |

#### 效果对比

| 指标 | FP32 | FP16 | 变化 |
|-----|------|------|------|
| 显存占用 | 100% | 50% | -50% |
| 生成速度 | 基准 | +30% | +30% |
| 图像质量 | 最高 | 几乎相同 | 轻微差异 |

#### 注意事项

- 某些情况下可能出现 NaN 错误
- 如遇问题，可尝试 BF16
- 默认情况下 ComfyUI 已启用 FP16

### BF16（Brain Float 16）

#### 功能描述

BF16 是一种改进的 16 位浮点格式，相比 FP16 有更好的数值范围和稳定性。

#### 使用场景

- RTX 30/40 系列显卡
- 需要更好的数值稳定性
- 遇到 FP16 的 NaN 问题

#### 支持的 GPU

| GPU 系列 | BF16 支持 |
|---------|---------|
| RTX 40 系列 | ✅ 完全支持 |
| RTX 30 系列 | ✅ 完全支持 |
| A100/H100 | ✅ 完全支持 |
| RTX 20 系列 | ❌ 不支持 |
| GTX 系列 | ❌ 不支持 |

#### 启用方法

```bash
python main.py --bf16-unet
```

#### 参数详解

| 参数 | 说明 | 推荐值 |
|-----|------|-------|
| `--bf16-unet` | U-Net 使用 BF16 | RTX 30/40 推荐 |
| `--bf16-vae` | VAE 使用 BF16 | 可选 |

#### FP16 vs BF16 对比

| 特性 | FP16 | BF16 |
|-----|------|------|
| 数值范围 | 较小 | 较大 |
| 精度 | 较高 | 较低 |
| 稳定性 | 一般 | 更好 |
| NaN 风险 | 较高 | 较低 |
| GPU 要求 | 所有 GPU | RTX 30/40+ |

### FP8 量化

#### 功能描述

FP8 是最新的量化技术，将模型进一步量化到 8 位，大幅降低显存占用。

#### 使用场景

- RTX 40 系列显卡
- 显存严重不足
- 运行超大模型

#### 支持的 GPU

| GPU | FP8 支持 |
|-----|---------|
| RTX 40 系列 | ✅ 支持 |
| H100 | ✅ 支持 |
| RTX 30 系列 | ❌ 不支持 |
| RTX 20 系列 | ❌ 不支持 |

#### 启用方法

```bash
python main.py --fp8_e4m3fn-unet
```

或同时量化文本编码器：

```bash
python main.py --fp8_e4m3fn-unet --fp8_e4m3fn-text-encoder
```

#### 参数详解

| 参数 | 说明 | 推荐值 |
|-----|------|-------|
| `--fp8_e4m3fn-unet` | U-Net 使用 FP8 E4M3FN 格式 | RTX 40 推荐 |
| `--fp8_e5m2fn-unet` | U-Net 使用 FP8 E5M2FN 格式 | 可选 |
| `--fp8_e4m3fn-text-encoder` | 文本编码器使用 FP8 | 可选 |

#### 效果对比

| 指标 | FP16 | FP8 | 变化 |
|-----|------|------|------|
| 显存占用 | 50% | 25% | -50% |
| 生成速度 | 基准 | +20% | +20% |
| 图像质量 | 高 | 轻微损失 | 可接受 |

## 模型分块加载

### 什么是模型分块加载？

模型分块加载是将大模型分割成多个部分，按需加载到显存，用完即释放，从而在低显存环境下运行大模型。

### 工作原理

```
完整模型 (24GB)
    ↓ 分块
块1 (2GB) → GPU 计算 → 释放
块2 (2GB) → GPU 计算 → 释放
块3 (2GB) → GPU 计算 → 释放
...
```

### 分块模式对比

| 模式 | 启动参数 | 显存占用 | 速度 | 适用场景 |
|-----|---------|---------|------|---------|
| 高显存 | 默认 | 100% | 最快 | 显存充足 |
| 正常 | --normalvram | ~70% | 较快 | 中等显存 |
| 低显存 | --lowvram | ~40% | 较慢 | 低显存 |
| 无显存 | --novram | ~20% | 最慢 | 极低显存 |

### --normalvram 模式

#### 功能描述

介于高显存和低显存之间的平衡模式，大部分模型在 GPU，部分权重在内存。

#### 使用场景

- 显存 8-12GB
- SDXL 模型
- 中等分辨率

#### 启用方法

```bash
python main.py --normalvram
```

#### 效果

- 显存占用减少约 30%
- 速度下降约 10-15%

### --lowvram 模式

#### 功能描述

低显存模式，模型权重主要存储在系统内存，计算时传输到 GPU。

#### 使用场景

- 显存 4-8GB
- SD 1.5 模型
- 512-768 分辨率

#### 启用方法

```bash
python main.py --lowvram
```

#### 效果

- 显存占用减少约 60%
- 速度下降约 30-50%
- 可运行原本无法运行的模型

### --novram 模式

#### 功能描述

极端低显存模式，几乎不使用 GPU 显存存储模型。

#### 使用场景

- 显存 <4GB
- 仅用于推理
- 对速度要求不高

#### 启用方法

```bash
python main.py --novram
```

#### 效果

- 显存占用减少约 80%
- 速度下降约 50-70%
- 可在极低显存下运行

### 自动模式

ComfyUI 支持自动选择显存模式：

```bash
python main.py --auto-launch
```

系统会根据检测到的显存自动选择合适的模式。

## 共享权重与缓存

### 共享权重

#### 功能描述

多个组件共享相同的模型权重，避免重复加载。

#### 应用场景

| 场景 | 共享方式 |
|-----|---------|
| 多 LoRA | 共享基础模型 |
| 多 ControlNet | 共享预处理器 |
| 批量生成 | 共享模型权重 |

#### 配置方法

ComfyUI 默认自动共享模型权重，无需额外配置。

### 模型缓存

#### 功能描述

ComfyUI 会缓存已加载的模型，避免重复加载。

#### 缓存类型

| 缓存类型 | 说明 |
|---------|------|
| Checkpoint 缓存 | 避免重复加载模型文件 |
| VAE 缓存 | 共享 VAE 实例 |
| CLIP 缓存 | 共享文本编码器 |

#### 清除缓存

```python
import comfy.model_management as mm

mm.unload_all_models()
```

### 内存管理参数

#### --reserve-vram

保留指定大小的显存，避免 OOM：

```bash
python main.py --reserve-vram 1.0
```

| 参数值 | 说明 | 推荐场景 |
|-------|------|---------|
| 0.5 | 保留 0.5GB | 极限使用 |
| 1.0 | 保留 1GB | 推荐值 |
| 2.0 | 保留 2GB | 保守配置 |

## 采样优化

### 采样器选择

不同采样器的速度差异明显：

| 采样器 | 相对速度 | 质量 | 推荐场景 |
|-------|---------|------|---------|
| euler | 最快 | 一般 | 快速预览 |
| euler_a | 快 | 好 | 日常使用（推荐） |
| dpmpp_2m | 中等 | 好 | 高质量生成 |
| dpmpp_2m_sde | 中等 | 很好 | 最佳质量 |
| dpmpp_sde | 慢 | 最好 | 最高质量 |
| uni_pc | 快 | 好 | 新算法 |

### 步数优化

| 步数 | 速度 | 质量 | 推荐场景 |
|-----|------|------|---------|
| 10-15 | 最快 | 可接受 | 快速预览 |
| 15-20 | 快 | 好 | 日常使用 |
| 20-30 | 中等 | 很好 | 高质量 |
| 30+ | 慢 | 最佳 | 最高质量 |

**推荐：** 对于大多数场景，15-25 步已足够。

### CFG Scale 优化

高 CFG Scale 会增加计算量：

| CFG Scale | 效果 | 速度影响 |
|----------|------|---------|
| 5-7 | 正常 | 最优 |
| 7-12 | 更强提示词遵循 | 略慢 |
| 12+ | 可能过饱和 | 较慢 |

**推荐：** 使用 5-8 范围内的值。

## 批量处理优化

### 批量大小选择

| 批量大小 | 显存利用 | 单张速度 | 推荐场景 |
|---------|---------|---------|---------|
| 1 | 低 | 慢 | 测试、调试 |
| 2-4 | 中 | 较快 | 日常使用 |
| 4-8 | 高 | 快 | 批量生成 |
| 8+ | 最高 | 最快 | 大批量（需显存支持） |

### 批量大小计算脚本

```python
def get_optimal_batch_size(vram_gb, resolution, model_type="sd15"):
    """
    根据显存计算最佳批量大小
    
    参数：
    - vram_gb: 显存大小（GB）
    - resolution: 分辨率
    - model_type: 模型类型（sd15/sdxl）
    """
    base_memory = {
        "sd15": {"512": 4, "768": 6, "1024": 8},
        "sdxl": {"512": 8, "768": 10, "1024": 12}
    }
    
    res_key = str(resolution) if str(resolution) in base_memory[model_type] else "1024"
    base = base_memory[model_type][res_key]
    
    available = vram_gb - base
    
    if available < 0:
        return 1
    elif available < 2:
        return 1
    elif available < 4:
        return 2
    elif available < 6:
        return 4
    elif available < 10:
        return 8
    else:
        return 16

print(get_optimal_batch_size(10, 512, "sd15"))
```

## 综合优化配置

### 低显存配置（4-6GB）

```bash
python main.py \
    --lowvram \
    --fp16-unet \
    --fp16-vae \
    --use-xformers \
    --reserve-vram 0.5
```

**参数说明：**
- `--lowvram`：启用低显存模式
- `--fp16-unet`：U-Net 使用 FP16
- `--fp16-vae`：VAE 使用 FP16
- `--use-xformers`：启用 xFormers 加速
- `--reserve-vram 0.5`：保留 0.5GB 显存

### 中等显存配置（8-12GB）

```bash
python main.py \
    --normalvram \
    --fp16-unet \
    --bf16-vae \
    --use-xformers
```

**参数说明：**
- `--normalvram`：启用正常显存模式
- `--bf16-vae`：VAE 使用 BF16（更稳定）

### 高显存配置（16GB+）

```bash
python main.py \
    --fp16-unet \
    --bf16-vae \
    --use-pytorch-cross-attention
```

**参数说明：**
- `--use-pytorch-cross-attention`：使用 SDPA

### 最高性能配置（24GB+）


## 常见问题 FAQ

### Q1: 如何选择合适的精度？

**选择建议：**

| GPU | 推荐精度 |
|-----|---------|
| RTX 40 系列 | BF16 或 FP8 |
| RTX 30 系列 | BF16 |
| RTX 20 系列 | FP16 |
| GTX 系列 | FP16 |

### Q2: 优化后图像质量会下降吗？

**回答：**

- FP16/BF16：几乎无影响
- FP8：轻微影响，通常不可察觉
- 低显存模式：无影响，只是速度变慢

### Q3: 如何判断优化是否生效？

**检查方法：**

1. 查看启动日志
2. 对比显存占用
3. 对比生成速度

### Q4: 多个优化参数可以组合使用吗？

**回答：** 可以，但需注意兼容性。

**推荐组合：**
```bash
python main.py --lowvram --fp16-unet --use-xformers
```

**不推荐组合：**
```bash
python main.py --use-xformers --use-pytorch-cross-attention
```
（两者互斥）

### Q5: 优化后出现 NaN 错误怎么办？

**解决方案：**

1. 尝试使用 BF16 替代 FP16
2. 降低 CFG Scale
3. 检查模型是否损坏
4. 更新 PyTorch 版本
