## 概述

### 什么是显存？

显存（Video Memory，VRAM）是显卡上的专用内存，用于存储 GPU 处理过程中需要的数据。与普通内存（RAM）不同，显存具有更高的带宽，专门为图形处理和深度学习计算优化。

### 为什么显存很重要？

| 重要性 | 说明 |
|-------|------|
| **模型加载** | 所有模型权重都需要加载到显存 |
| **计算过程** | 中间计算结果占用大量显存 |
| **分辨率限制** | 分辨率越高，显存需求越大 |
| **批量处理** | 批量大小直接影响显存占用 |

### 显存不足会发生什么？

当显存不足时，会出现 **OOM（Out of Memory）** 错误：
- 生成中断，无法完成
- 程序崩溃
- 系统变卡

## 显存占用基础

### 显存用途分类

| 类型 | 说明 | 占用特点 | 管理方式 |
|-----|------|---------|---------|
| **模型权重** | 神经网络参数 | 固定，加载后不变 | 卸载到内存 |
| **激活值** | 中间计算结果 | 动态，随分辨率变化 | 难以优化 |
| **Latent** | 潜空间数据 | 与分辨率相关 | 占用较小 |
| **临时缓存** | 计算中间值 | 动态分配释放 | 自动管理 |

### 基础显存占用

ComfyUI 启动后的基础显存占用约 **500MB - 1GB**，包括：

| 组件 | 占用 | 说明 |
|-----|------|------|
| PyTorch 运行时 | ~300MB | 深度学习框架 |
| CUDA 上下文 | ~200MB | GPU 计算环境 |
| 基础库加载 | ~100MB | 依赖库 |
| ComfyUI 核心 | ~100MB | 工作流引擎 |

## 模型显存占用详解

### Checkpoint 模型

Checkpoint 是占用显存最大的组件：

| 模型类型 | 参数量 | FP16 显存 | FP32 显存 | 推荐显卡 |
|---------|-------|----------|----------|---------|
| SD 1.5 | 0.98B | ~2GB | ~4GB | 6GB+ |
| SD 2.1 | 0.87B | ~1.8GB | ~3.6GB | 6GB+ |
| SDXL | 2.6B | ~5GB | ~10GB | 10GB+ |
| SD3 Medium | 2B | ~4GB | ~8GB | 8GB+ |
| Flux.1 Dev | 12B | ~24GB | ~48GB | 24GB+ |
| Flux.1 Schnell | 12B | ~24GB | ~48GB | 24GB+ |

### VAE 模型

VAE 负责图像编解码，占用相对较小：

| VAE 类型 | 显存占用 | 说明 |
|---------|---------|------|
| SD 1.5 VAE | ~50MB | 标准 VAE |
| SDXL VAE | ~100MB | 更大模型 |
| FLUX VAE | ~200MB | 最新模型 |
| 自定义 VAE | 50-200MB | 如 vae-ft-mse |

### CLIP 模型

CLIP 负责文本编码：

| CLIP 类型 | 显存占用 | 使用场景 |
|----------|---------|---------|
| CLIP ViT-L/14 (SD 1.5) | ~350MB | SD 1.5 系列 |
| CLIP ViT-G/14 (SDXL) | ~700MB | SDXL 系列 |
| OpenCLIP ViT-bigG/14 | ~1.4GB | SDXL 双编码器 |
| T5-XXL (Flux) | ~5GB | Flux 系列 |

### ControlNet 模型

| ControlNet 类型 | 显存占用 | 说明 |
|----------------|---------|------|
| SD 1.5 ControlNet | ~700MB | 单个 ControlNet |
| SDXL ControlNet | ~1.5GB | 单个 ControlNet |
| 多 ControlNet | 累加 | 每个 ControlNet 独立占用 |

**示例：**
- 1 个 SD 1.5 ControlNet：+700MB
- 2 个 SD 1.5 ControlNet：+1.4GB
- 3 个 SD 1.5 ControlNet：+2.1GB

### LoRA 模型

| LoRA 类型 | 显存占用 | 说明 |
|----------|---------|------|
| 标准 LoRA (rank=128) | ~50-100MB | 常用配置 |
| LoRA (rank=64) | ~30-50MB | 中等配置 |
| LoRA (rank=32) | ~20-30MB | 轻量配置 |
| LyCORIS | ~30-80MB | 其他微调方式 |

## Latent 显存占用

### 什么是 Latent？

Latent 是图像在潜空间的表示，是扩散模型的核心数据结构。分辨率越高，Latent 越大。

### 不同分辨率的 Latent 占用

| 分辨率 | Latent 尺寸 | 单张显存 | 计算公式 |
|-------|------------|---------|---------|
| 512x512 | 64x64 | ~50KB | 64×64×4×4字节 |
| 768x768 | 96x96 | ~110KB | 96×96×4×4字节 |
| 1024x1024 | 128x128 | ~200KB | 128×128×4×4字节 |
| 1536x1536 | 192x192 | ~450KB | 192×192×4×4字节 |
| 2048x2048 | 256x256 | ~800KB | 256×256×4×4字节 |

### 批量 Latent 占用

| 批量大小 | 512x512 | 1024x1024 |
|---------|---------|-----------|
| 1 | ~50KB | ~200KB |
| 4 | ~200KB | ~800KB |
| 8 | ~400KB | ~1.6MB |
| 16 | ~800KB | ~3.2MB |

**注意：** Latent 本身占用很小，但计算过程中的激活值占用较大。

---

## 激活值显存占用

### 什么是激活值？

激活值是神经网络在计算过程中产生的中间结果。这是显存占用的主要来源，也是最难优化的部分。

### 采样过程显存

| 分辨率 | 估算激活值显存 | 说明 |
|-------|--------------|------|
| 512x512 | ~1-2GB | SD 1.5 标准分辨率 |
| 768x768 | ~2-4GB | 中等分辨率 |
| 1024x1024 | ~4-6GB | SDXL 标准分辨率 |
| 1536x1536 | ~8-12GB | 高分辨率 |
| 2048x2048 | ~12-18GB | 超高分辨率 |

### 影响因素

| 因素 | 影响 | 说明 |
|-----|------|------|
| 分辨率 | 🔴 平方级增长 | 分辨率翻倍，显存约 4 倍 |
| 批量大小 | 🔴 线性增长 | 批量翻倍，显存翻倍 |
| 采样步数 | 🟡 轻微影响 | 步数增加，显存略增 |
| 采样器类型 | 🟡 轻微影响 | 不同采样器略有差异 |

## 显存监控方法（详细操作步骤）

### 方法一：Windows 任务管理器

#### 操作步骤

1. **打开任务管理器**
   - 按 `Ctrl + Shift + Esc` 快捷键
   - 或右键点击任务栏，选择"任务管理器"

2. **切换到"性能"选项卡**
   - 点击顶部的"性能"标签

3. **选择 GPU**
   - 在左侧列表中找到"GPU"
   - 如果有多个 GPU，会显示 GPU 0、GPU 1 等

4. **查看显存信息**
   - **专用 GPU 内存**：当前显存使用情况
   - **共享 GPU 内存**：使用系统内存作为显存
   - **GPU 内存**：总显存大小

5. **实时监控**
   - 保持任务管理器窗口打开
   - 运行 ComfyUI 时观察显存变化

### 方法三：Python 代码监控

#### 基础监控脚本

```python
import torch

def print_gpu_memory():
    if not torch.cuda.is_available():
        print("CUDA 不可用")
        return
    
    allocated = torch.cuda.memory_allocated(0) / 1024**3
    reserved = torch.cuda.memory_reserved(0) / 1024**3
    total = torch.cuda.get_device_properties(0).total_memory / 1024**3
    
    print(f"GPU: {torch.cuda.get_device_name(0)}")
    print(f"总显存: {total:.2f} GB")
    print(f"已分配: {allocated:.2f} GB")
    print(f"已保留: {reserved:.2f} GB")
    print(f"可用: {total - reserved:.2f} GB")

print_gpu_memory()
```

#### 实时监控脚本

```python
import torch
import time

def monitor_gpu(interval=1, duration=60):
    """
    实时监控 GPU 显存
    
    参数：
    - interval: 刷新间隔（秒）
    - duration: 监控时长（秒）
    """
    if not torch.cuda.is_available():
        print("CUDA 不可用")
        return
    
    print("开始监控 GPU 显存...")
    print("-" * 60)
    print(f"{'时间':<10} {'已分配(GB)':<15} {'已保留(GB)':<15} {'利用率':<10}")
    print("-" * 60)
    
    start_time = time.time()
    while time.time() - start_time < duration:
        allocated = torch.cuda.memory_allocated(0) / 1024**3
        reserved = torch.cuda.memory_reserved(0) / 1024**3
        
        elapsed = time.time() - start_time
        print(f"{elapsed:<10.1f} {allocated:<15.2f} {reserved:<15.2f}")
        
        time.sleep(interval)

monitor_gpu(interval=0.5, duration=30)
```

#### 在 ComfyUI 中使用

```python
import torch

class MemoryMonitor:
    def __init__(self):
        self.peak_memory = 0
    
    def update_peak(self):
        current = torch.cuda.memory_allocated(0) / 1024**3
        if current > self.peak_memory:
            self.peak_memory = current
        return current
    
    def get_report(self):
        total = torch.cuda.get_device_properties(0).total_memory / 1024**3
        return {
            "total": f"{total:.2f} GB",
            "peak": f"{self.peak_memory:.2f} GB",
            "current": f"{torch.cuda.memory_allocated(0) / 1024**3:.2f} GB"
        }

monitor = MemoryMonitor()
```

## 显存不足的表现与解决

### 常见错误信息

#### 错误类型一：CUDA OOM

```
CUDA out of memory. Tried to allocate 2.00 GiB
```

**含义：** 尝试分配 2GB 显存失败，显存不足。

#### 错误类型二：Runtime Error

```
RuntimeError: CUDA error: out of memory
```

**含义：** CUDA 运行时错误，显存耗尽。

#### 错误类型三：Allocation Failed

```
RuntimeError: CUDA driver error: out of memory
```

**含义：** 驱动层面显存不足。

### 解决方案优先级

| 优先级 | 解决方案 | 效果 | 操作难度 |
|-------|---------|------|---------|
| 1 | 降低分辨率 | ⭐⭐⭐⭐⭐ | 简单 |
| 2 | 启用低显存模式 | ⭐⭐⭐⭐⭐ | 简单 |
| 3 | 减少批量大小 | ⭐⭐⭐⭐ | 简单 |
| 4 | 使用 FP16 | ⭐⭐⭐⭐ | 简单 |
| 5 | 启用 xFormers | ⭐⭐⭐ | 中等 |
| 6 | 减少 ControlNet | ⭐⭐⭐ | 简单 |
| 7 | 使用 CPU VAE | ⭐⭐ | 简单 |

### 详细解决步骤

#### 步骤 1：降低分辨率

```
原设置：1024x1024
新设置：512x512 或 768x768
```

#### 步骤 2：启用低显存模式

```bash
python main.py --lowvram
```

#### 步骤 3：减少批量大小

在 `Empty Latent Image` 节点中：
```
batch_size: 1  # 从 4 改为 1
```

#### 步骤 4：使用 FP16

```bash
python main.py --fp16-unet --fp16-vae
```

#### 步骤 5：启用 xFormers

```bash
python main.py --use-xformers
```

#### 步骤 6：减少 ControlNet

- 只使用必要的 ControlNet
- 使用轻量级预处理器

#### 步骤 7：使用 CPU VAE

```bash
python main.py --cpu-vae
```

## 常见问题 FAQ

### Q1: 为什么我的显存占用比预期高？

**可能原因：**

| 原因 | 检查方法 | 解决方案 |
|-----|---------|---------|
| 后台程序占用 | 任务管理器检查 | 关闭其他 GPU 程序 |
| 浏览器 GPU 加速 | 检查浏览器设置 | 关闭硬件加速 |
| 模型未卸载 | 查看模型缓存 | 切换模型时清理缓存 |
| 显存碎片 | 长时间运行后 | 重启 ComfyUI |

### Q2: 如何判断需要多少显存？

**估算方法：**

1. 基础占用：~1GB
2. 模型占用：查看本章表格
3. 激活值：分辨率对应值
4. 预留空间：+1-2GB

**示例计算（SDXL 1024x1024）：**
```
基础: 1GB
模型: 5GB
CLIP: 1GB
激活值: 5GB
预留: 2GB
总计: 14GB（建议 16GB 显卡）
```

### Q3: 共享 GPU 内存是什么？

**说明：**
- 当显存不足时，系统会使用普通内存
- 速度比显存慢很多
- 出现共享内存使用时，说明显存紧张

### Q4: 如何清理显存？

**方法一：重启 ComfyUI**
```bash
# 关闭 ComfyUI
Ctrl + C

# 重新启动
python main.py
```

**方法二：Python 代码清理**
```python
import torch
import gc

gc.collect()
torch.cuda.empty_cache()
```

### Q5: 多显卡如何分配显存？

**方法一：指定 GPU**
```bash
CUDA_VISIBLE_DEVICES=0 python main.py
```

**方法二：多实例运行**
```bash
# 终端 1
CUDA_VISIBLE_DEVICES=0 python main.py --port 8188

# 终端 2
CUDA_VISIBLE_DEVICES=1 python main.py --port 8189
```
