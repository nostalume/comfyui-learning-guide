## 概述

### 什么是低显存模式？

低显存模式是 ComfyUI 提供的一种特殊运行模式，通过模型分块、权重卸载等技术，允许在显存较小的 GPU 上运行原本需要更大显存的模型。

### 为什么需要低显存模式？

| 原因 | 说明 |
|-----|------|
| **硬件限制** | 显卡显存不足，无法直接运行模型 |
| **大模型支持** | 想要运行 SDXL、Flux 等大模型 |
| **高分辨率** | 需要生成更高分辨率的图像 |
| **成本节约** | 不想升级硬件也能使用 |

### 低显存模式能做什么？

| 显存 | 无优化 | 低显存模式 |
|-----|-------|-----------|
| 4GB | ❌ 无法运行 SD 1.5 | ✅ 可运行 SD 1.5 512x512 |
| 6GB | ⚠️ SD 1.5 有限制 | ✅ SD 1.5 全功能 |
| 8GB | ⚠️ SDXL 受限 | ✅ SDXL 1024x1024 |

## 显存模式对比

### 四种显存模式

| 模式 | 启动参数 | 显存需求 | 速度 | 说明 |
|-----|---------|---------|------|------|
| **高显存** | 默认 | 12GB+ | 最快 | 模型全部加载到 GPU |
| **正常** | --normalvram | 8-12GB | 快 | 部分模型卸载到内存 |
| **低显存** | --lowvram | 4-8GB | 较慢 | 大部分模型在内存 |
| **无显存** | --novram | <4GB | 慢 | 模型全部在内存 |

### 模式选择指南

```
你的显存是多少？
    │
    ├── 24GB+ → 默认模式（高显存）
    │
    ├── 16GB → 默认模式 或 --normalvram
    │
    ├── 12GB → --normalvram
    │
    ├── 8GB → --normalvram 或 --lowvram
    │
    ├── 6GB → --lowvram
    │
    └── 4GB → --lowvram 或 --novram
```

### 自动模式

ComfyUI 支持自动选择显存模式：

```bash
python main.py --auto-launch
```

系统会根据检测到的显存自动选择合适的模式。

## 低显存模式详解

### --lowvram 模式

#### 功能描述

低显存模式，模型权重主要存储在系统内存（RAM），计算时将需要的部分传输到 GPU 显存，计算完成后释放。

#### 工作原理

```
系统内存 (RAM)
    │
    ├── 模型权重存储在这里
    │
    ↓ 计算时传输
GPU 显存
    │
    ├── 接收部分模型权重
    ├── 执行计算
    ├── 释放显存
    │
    ↓ 重复
下一个模型块...
```

#### 使用场景

- 显存 4-8GB
- SD 1.5 模型
- 512-768 分辨率
- SDXL 低分辨率

#### 启用方法

```bash
python main.py --lowvram
```

#### 性能影响

| 指标 | 正常模式 | 低显存模式 | 变化 |
|-----|---------|-----------|------|
| 显存占用 | 100% | ~40% | -60% |
| 生成速度 | 基准 | -30~50% | 变慢 |
| 可运行模型 | 受限 | 更大模型 | 改善 |

### --normalvram 模式

#### 功能描述

介于高显存和低显存之间的平衡模式。大部分模型在 GPU，部分权重在内存，按需交换。

#### 使用场景

- 显存 8-12GB
- SDXL 模型
- 中等分辨率
- 需要平衡速度和显存

#### 启用方法

```bash
python main.py --normalvram
```

#### 性能影响

| 指标 | 高显存模式 | normalvram | 变化 |
|-----|----------|-----------|------|
| 显存占用 | 100% | ~70% | -30% |
| 生成速度 | 基准 | -10~15% | 略慢 |

### --novram 模式

#### 功能描述

极端低显存模式，几乎不使用 GPU 显存存储模型，所有模型权重都在系统内存。

#### 使用场景

- 显存 <4GB
- 仅用于推理
- 对速度要求不高
- 极限情况

#### 启用方法

```bash
python main.py --novram
```

#### 性能影响

| 指标 | 正常模式 | novram | 变化 |
|-----|---------|--------|------|
| 显存占用 | 100% | ~20% | -80% |
| 生成速度 | 基准 | -50~70% | 很慢 |

## 配合参数详解

### --reserve-vram

#### 功能描述

保留指定大小的显存作为缓冲，避免 OOM 错误。

#### 使用场景

- 显存刚好够用
- 经常出现 OOM
- 需要稳定运行

#### 启用方法

```bash
python main.py --lowvram --reserve-vram 1.0
```

#### 参数详解

| 参数值 | 说明 | 推荐场景 |
|-------|------|---------|
| 0.5 | 保留 0.5GB | 极限使用，可能不稳定 |
| 1.0 | 保留 1GB | 推荐值，稳定运行 |
| 1.5 | 保留 1.5GB | 保守配置 |
| 2.0 | 保留 2GB | 非常保守 |

### --fp16-unet

#### 功能描述

U-Net 使用 FP16 精度，减少显存占用。

#### 使用场景

- 所有显存配置
- 需要减少显存占用

#### 启用方法

```bash
python main.py --lowvram --fp16-unet
```

#### 效果

- 显存减少约 50%
- 速度提升约 20-30%

### --fp16-vae

#### 功能描述

VAE 使用 FP16 精度。

#### 启用方法

```bash
python main.py --lowvram --fp16-vae
```

### --cpu-vae

#### 功能描述

将 VAE 计算放到 CPU，节省显存。

#### 使用场景

- 显存极度紧张
- 可以接受解码变慢

#### 启用方法

```bash
python main.py --lowvram --cpu-vae
```

#### 效果

- 节省约 100-200MB 显存
- 解码速度变慢 2-3 倍

### --use-xformers

#### 功能描述

启用 xFormers 加速，同时减少显存占用。

#### 启用方法

```bash
python main.py --lowvram --use-xformers
```

#### 效果

- 速度提升 20-30%
- 显存减少 10-20%

## 低显存优化技巧

### 技巧一：降低分辨率

分辨率对显存影响最大，呈平方级增长。

#### 分辨率与显存关系

| 分辨率 | 相对显存 | 像素数 |
|-------|---------|-------|
| 512x512 | 1x | 262,144 |
| 768x768 | 2.25x | 589,824 |
| 1024x1024 | 4x | 1,048,576 |
| 1536x1536 | 9x | 2,359,296 |

#### 推荐策略

**先生成低分辨率，再用高清修复放大：**

1. 生成 512x512 基础图像
2. 使用 Hires Fix 放大到 1024x1024
3. 比直接生成 1024x1024 更省显存

### 技巧二：减少批量大小

批量大小直接影响显存占用。

#### 设置方法

在 `Empty Latent Image` 节点中：

```
batch_size: 1  # 低显存使用批量大小 1
```

#### 批量大小与显存

| 批量大小 | 显存占用 | 说明 |
|---------|---------|------|
| 1 | 基准 | 低显存推荐 |
| 2 | +50% | 需要更多显存 |
| 4 | +100% | 高显存可用 |

### 技巧三：使用更轻量的模型

| 模型 | 显存需求 | 质量 | 速度 |
|-----|---------|------|------|
| SD 1.5 | ~4GB | 好 | 快 |
| SD 2.1 | ~4GB | 好 | 快 |
| SDXL | ~8GB | 很好 | 中 |
| SDXL Turbo | ~6GB | 好 | 很快 |
| Flux.1 Schnell | ~12GB | 极好 | 慢 |

### 技巧四：避免多 ControlNet

每个 ControlNet 增加约 700MB-1.5GB 显存。

#### 推荐做法

- 低显存时只使用 1 个 ControlNet
- 使用轻量级预处理器
- 必要时使用 CPU 预处理

### 技巧五：使用 CPU VAE

当显存极度紧张时，可以将 VAE 计算放到 CPU。

```bash
python main.py --lowvram --cpu-vae
```

**效果：**
- 节省 100-200MB 显存
- 解码速度变慢 2-3 倍

## 显存监控与调试

### 实时监控

#### Windows PowerShell

```powershell
while ($true) { cls; nvidia-smi; Start-Sleep -Seconds 1 }
```

#### Linux/macOS

```bash
watch -n 1 nvidia-smi
```

### Python 监控脚本

```python
import torch
import time

def monitor_memory_during_generation(interval=0.5):
    """在生成过程中监控显存"""
    print("开始监控显存...")
    print("-" * 50)
    
    peak_memory = 0
    
    try:
        while True:
            if torch.cuda.is_available():
                allocated = torch.cuda.memory_allocated(0) / 1024**3
                reserved = torch.cuda.memory_reserved(0) / 1024**3
                
                if allocated > peak_memory:
                    peak_memory = allocated
                
                print(f"已分配: {allocated:.2f}GB | 已保留: {reserved:.2f}GB | 峰值: {peak_memory:.2f}GB")
            
            time.sleep(interval)
    except KeyboardInterrupt:
        print(f"\n监控结束，峰值显存: {peak_memory:.2f}GB")

monitor_memory_during_generation()
```

### 显存碎片整理

长时间运行后，显存可能产生碎片：

```python
import torch
import gc

def clean_memory():
    """清理显存"""
    gc.collect()
    torch.cuda.empty_cache()
    torch.cuda.synchronize()
    print("显存已清理")

clean_memory()
```

## 常见问题 FAQ

### Q1: 出现 OOM 错误怎么办？

**错误信息：**
```
CUDA out of memory. Tried to allocate X.XX GiB
```

**解决步骤：**

| 步骤 | 操作 | 命令 |
|-----|------|------|
| 1 | 启用低显存模式 | `--lowvram` |
| 2 | 降低分辨率 | 512x512 |
| 3 | 减少批量大小 | batch_size=1 |
| 4 | 启用 FP16 | `--fp16-unet` |
| 5 | 启用 xFormers | `--use-xformers` |
| 6 | 减少 ControlNet | 只用 1 个 |
| 7 | 使用 CPU VAE | `--cpu-vae` |

### Q2: 低显存模式速度太慢怎么办？

**原因：** 频繁的内存-GPU 数据传输

**缓解方法：**

| 方法 | 效果 | 操作 |
|-----|------|------|
| 使用 --normalvram | 速度提升 20-30% | 如显存允许 |
| 减少采样步数 | 速度提升 | 15-20 步 |
| 使用更快采样器 | 速度提升 | euler_a |
| 减少分辨率 | 速度提升 | 512x512 |

### Q3: 生成过程中断怎么办？

**原因：** 显存不足导致进程崩溃

**解决方案：**

| 方案 | 操作 |
|-----|------|
| 增加保留显存 | `--reserve-vram 1.5` |
| 检查后台程序 | 关闭其他 GPU 程序 |
| 关闭浏览器 GPU 加速 | 浏览器设置中关闭 |
| 重启 ComfyUI | 清理显存碎片 |

### Q4: 如何判断应该用哪种模式？

**判断方法：**

```
你的显存是多少？
    │
    ├── ≥12GB → 默认模式
    │
    ├── 8-12GB → --normalvram
    │
    ├── 4-8GB → --lowvram
    │
    └── <4GB → --novram
```

### Q5: 低显存模式会影响图像质量吗？

**回答：** 不会。

低显存模式只是改变了模型的存储和计算方式，不影响：
- 生成算法
- 模型权重
- 随机种子

唯一的区别是速度变慢。

### Q6: 如何在低显存下运行 SDXL？

**推荐配置（8GB 显存）：**

```bash
python main.py \
    --lowvram \
    --fp16-unet \
    --fp16-vae \
    --use-xformers \
    --reserve-vram 0.5
```

**工作流设置：**
- 分辨率：1024x1024
- 批量大小：1
- 采样步数：20
- 采样器：euler_a

## 最佳实践总结

### 配置优先级

1. **首先**：选择合适的显存模式
2. **其次**：启用精度优化（FP16）
3. **然后**：启用加速工具（xFormers）
4. **最后**：调整工作流参数

### 不同显存的最佳配置

| 显存 | 模式 | 精度 | 加速 | 可运行模型 |
|-----|------|------|------|-----------|
| 4GB | --lowvram | FP16 | xFormers | SD 1.5 |
| 6GB | --lowvram | FP16 | xFormers | SD 1.5, SDXL(低显存) |
| 8GB | --normalvram | FP16 | xFormers | SD 1.5, SDXL |
| 10GB | --normalvram | FP16 | xFormers | SD 1.5, SDXL, Flux(低显存) |
| 12GB+ | 默认 | BF16 | SDPA | 所有模型 |

### 性能优化检查清单

- [ ] 启用合适的显存模式
- [ ] 使用 FP16/BF16 精度
- [ ] 启用 xFormers 或 SDPA
- [ ] 设置合适的保留显存
- [ ] 调整分辨率和批量大小
- [ ] 选择高效的采样器
- [ ] 关闭不必要的后台程序
