### 步骤 2: 条件分支设计

**目标：** 学会使用条件节点实现动态工作流

#### 2.1 理解条件分支

条件分支允许工作流根据条件选择不同的执行路径：

```
                    ┌── 条件为真 ──→ 路径 A
输入 → 条件判断 ────┤
                    └── 条件为假 ──→ 路径 B
```

#### 2.2 创建简单条件分支工作流

**场景：** 根据开关选择不同的模型

**步骤：**

1. **添加 Primitive 节点**
   - 双击空白处，搜索 "Primitive"
   - 选择 "Primitive (Boolean)"
   - 这个节点将作为条件开关

2. **添加两个 Checkpoint Loader 节点**
   - 添加两个 "Load Checkpoint（加载模型）" 节点
   - 第一个加载写实模型
   - 第二个加载动漫模型

3. **添加 ImpactIf 节点**
   - 搜索 "ImpactIf" 并添加
   - 这是条件判断的核心节点

4. **连接节点**
   ```
   Primitive (Boolean) → ImpactIf.condition
   Checkpoint Loader 1 → ImpactIf.if_true
   Checkpoint Loader 2 → ImpactIf.if_false
   ImpactIf.output → 后续节点（如 KSampler）
   ```

#### 2.3 ImpactIf 节点参数详解

| 参数名 | 类型 | 说明 | 示例 |
|-------|------|------|------|
| condition | BOOLEAN | 判断条件 | True/False |
| if_true | ANY | 条件为真时的输出 | 模型1 |
| if_false | ANY | 条件为假时的输出 | 模型2 |

#### 2.4 实战：风格切换工作流

创建一个可以在"写实风格"和"动漫风格"之间切换的工作流：

**完整节点列表：**

| 序号 | 节点名称 | 参数设置 |
|-----|---------|---------|
| 1 | Primitive (Boolean) | 默认值：True，命名为 "UseAnimeStyle" |
| 2 | Load Checkpoint | 模型：realisticVisionV51 |
| 3 | Load Checkpoint | 模型：anything-v4.5 |
| 4 | CLIP Text Encode（CLIP文本编码器） (正面) | 提示词：根据风格设置 |
| 5 | CLIP Text Encode (负面) | 提示词：通用负面词 |
| 6 | Empty Latent Image（空Latent图像） | 尺寸：512×512 |
| 7 | ImpactIf | 连接上述节点 |
| 8 | KSampler（K采样器） | 步数：20，CFG：7 |
| 9 | VAE Decode（VAE解码） | - |
| 10 | Save Image（保存图像） | - |

**连接方式：**

```
[Primitive: UseAnimeStyle]
        │
        ▼
    [ImpactIf] ◄─── [Checkpoint: 写实模型] (if_false)
        │            [Checkpoint: 动漫模型] (if_true)
        ▼
   [KSampler] ◄─── [CLIP Text Encode]
        │
        ▼
  [VAE Decode]
        │
        ▼
  [Save Image]
```

### 步骤 3: 动态参数控制

**目标：** 学会将参数外部化，创建可配置的工作流

#### 3.1 Primitive 节点类型

| 节点名称 | 输出类型 | 用途 |
|---------|---------|------|
| Primitive (Boolean) | BOOLEAN | 开关控制 |
| Primitive (Integer) | INT | 数值参数 |
| Primitive (Float) | FLOAT | 浮点参数 |
| Primitive (String) | STRING | 文本参数 |
| Primitive (Seed) | SEED | 随机种子 |

#### 3.2 创建参数控制面板

**目标：** 将常用参数集中到工作流顶部

**添加以下 Primitive 节点：**

1. **Seed 节点**
   - 搜索 "Primitive (Seed)"
   - 连接到 KSampler 的 seed 输入

2. **Steps 节点**
   - 搜索 "Primitive (Integer)"
   - 设置：默认 20，最小 1，最大 50
   - 连接到 KSampler 的 steps 输入

3. **CFG 节点**
   - 搜索 "Primitive (Float)"
   - 设置：默认 7.0，最小 1.0，最大 20.0
   - 连接到 KSampler 的 cfg 输入

4. **Width/Height 节点**
   - 搜索 "Primitive (Integer)"
   - 设置：默认 512，最小 256，最大 1024
   - 连接到 Empty Latent Image 的尺寸输入

5. **Prompt 节点**
   - 搜索 "Primitive (String)"
   - 连接到 CLIP Text Encode 的 text 输入

#### 3.3 参数外部化的好处

| 好处 | 说明 |
|-----|------|
| 易于调整 | 参数集中在顶部，无需查找 |
| 模板化 | 保存后可作为模板复用 |
| 清晰明了 | 工作流结构更清晰 |
| 便于分享 | 其他用户容易理解参数 |

### 步骤 4: 循环处理机制

**目标：** 学会使用循环节点批量处理

#### 4.1 理解循环处理

循环处理允许对多个输入执行相同的操作：

```
输入列表 → 循环节点 → 处理节点 → 收集节点 → 结果列表
              │
              └── 自动遍历每个元素
```

#### 4.2 Impact Pack 循环节点

| 节点名称 | 功能 | 使用场景 |
|---------|------|---------|
| ImpactIterate | 遍历数组元素 | 批量处理 |
| ImpactCollect | 收集循环结果 | 汇总输出 |
| ImpactMakeTileBatch | 创建批次 | 图像分块 |

#### 4.3 实战：批量生成不同风格图像

**目标：** 使用同一个工作流生成多张不同风格的图像

**步骤：**

1. **创建提示词数组**
   - 使用多个 Primitive (String) 节点
   - 每个节点设置不同的提示词

2. **添加循环节点**
   - 添加 ImpactIterate 节点
   - 将提示词连接到循环输入

3. **连接处理流程**
   ```
   [提示词数组] → [ImpactIterate] → [CLIP Text Encode] → [KSampler] → [ImpactCollect]
   ```

4. **收集结果**
   - 添加 ImpactCollect 节点
   - 收集所有生成的图像

#### 4.4 循环工作流注意事项

| 注意事项 | 说明 |
|---------|------|
| 内存占用 | 循环会累积中间结果，注意显存 |
| 执行时间 | 循环次数越多，执行时间越长 |
| 错误处理 | 单次循环失败可能影响整体 |
| 结果顺序 | 收集的结果按循环顺序排列 |

### 步骤 5: 错误处理机制

**目标：** 学会处理工作流执行中的异常

#### 5.1 常见错误类型

| 错误类型 | 原因 | 影响 |
|---------|------|------|
| 模型加载失败 | 模型文件损坏或不存在 | 工作流中断 |
| 显存不足 | 生成过程中显存耗尽 | 生成失败 |
| 参数错误 | 参数值超出范围 | 结果异常 |
| 节点连接错误 | 连接类型不匹配 | 无法执行 |

#### 5.2 使用条件停止节点

**ImpactConditionalStop 节点：**

用于在特定条件下停止工作流执行：

```
[条件判断] → [ImpactConditionalStop] → [后续节点]
                    │
                    └── 条件不满足时停止
```

#### 5.3 错误处理最佳实践

1. **参数验证**
   - 使用 Primitive 节点限制参数范围
   - 避免用户输入无效值

2. **资源检查**
   - 确保模型文件存在
   - 检查显存是否充足

3. **降级策略**
   - 准备备用模型
   - 设置默认输出

4. **日志记录**
   - 记录执行过程中的关键信息
   - 便于问题排查

### 步骤 6: 工作流模板化

**目标：** 创建可复用的工作流模板

#### 6.1 设计原则

| 原则 | 说明 | 实现方法 |
|-----|------|---------|
| 参数外部化 | 所有可变参数使用 Primitive 节点 | Primitive 节点 |
| 模块化 | 相关节点分组，使用颜色区分 | 节点颜色标记 |
| 清晰注释 | 为关键节点添加说明 | 注释节点 |
| 版本控制 | 定期保存工作流版本 | 文件命名 |

#### 6.2 工作流区域划分

```
┌─────────────────────────────────────────────────────────────┐
│                    【参数区域】（红色）                        │
│  [Seed] [Steps] [CFG] [Width] [Height] [Prompt]             │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    【模型区域】（蓝色）                        │
│  [Checkpoint Loader] [CLIP] [VAE]                           │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    【处理区域】（绿色）                        │
│  [KSampler] [VAE Decode]                                    │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    【输出区域】（黄色）                        │
│  [Save Image] [Preview Image]                               │
└─────────────────────────────────────────────────────────────┘
```

#### 6.3 节点颜色标记

## ❓ 常见问题

### Q1: Impact Pack 安装后节点不显示

**原因分析：**
- 安装不完整
- 依赖未安装
- ComfyUI 未重启

**解决方案：**

```bash
# 检查目录是否存在
ls custom_nodes/ComfyUI-Impact-Pack

# 重新安装依赖
cd custom_nodes/ComfyUI-Impact-Pack
pip install -r requirements.txt

# 重启 ComfyUI
python main.py
```

### Q2: ImpactIf 节点连接后报错

**原因分析：**
- 连接类型不匹配
- if_true 和 if_false 类型不一致

**解决方案：**

确保 if_true 和 if_false 输入的是相同类型的数据：

```
正确示例：
- if_true: MODEL 类型
- if_false: MODEL 类型

错误示例：
- if_true: MODEL 类型
- if_false: CLIP 类型  ← 类型不匹配
```

### Q3: 循环节点无法正常工作

**原因分析：**
- 输入不是数组格式
- 循环内部节点连接错误

**解决方案：**

1. 确保输入是数组格式
2. 检查循环内部的节点连接
3. 确保使用 ImpactCollect 收集结果

### Q4: 如何保存工作流模板

**方法：**

1. 点击菜单 `File > Save`
2. 保存为 `.json` 文件
3. 下次使用 `File > Load` 加载

**命名建议：**

```
模板名称_版本号_日期.json

示例：
style_switch_v1.0_20241201.json
batch_generate_v2.1_20241215.json
```

### Q5: 工作流太复杂，如何简化

**简化方法：**

1. **使用子工作流**
   - 将复杂工作流拆分为多个简单工作流
   - 分别保存和测试

2. **使用节点组**
   - 将相关节点分组
   - 使用颜色标记区分

3. **添加注释**
   - 为关键节点添加注释
   - 说明节点的作用

### Q6: 如何分享工作流给他人

**分享步骤：**

1. **导出工作流**
   - `File > Save` 保存 JSON 文件

2. **导出图片预览**
   - `File > Export Image` 导出工作流截图

3. **说明依赖**
   - 列出所需的扩展
   - 列出所需的模型

4. **打包分享**
   - 将 JSON、截图、说明打包
   - 上传到分享平台
