## 🚀 实战步骤

### 步骤 1: 理解两种高清修复方法

#### 方法对比

| 对比项 | 模型放大（Upscale） | Hires Fix |
|-------|-------------------|-----------|
| 原理 | 使用 AI 模型放大图像 | 放大后重新采样增强细节 |
| 速度 | 快 | 较慢 |
| 质量 | 好 | 更好 |
| 显存消耗 | 低 | 高 |
| 适用场景 | 快速放大、已有图像放大 | 从头生成高清图像 |

#### 方法选择指南

| 需求 | 推荐方法 | 说明 |
|-----|---------|------|
| 快速放大已有图像 | 模型放大 | 简单直接 |
| 生成高质量高清图 | Hires Fix | 效果更好 |
| 显存有限 | 模型放大 | 显存消耗低 |
| 追求最佳质量 | Hires Fix | 细节更丰富 |

### 步骤 2: 方法一 - 模型放大（Upscale）

#### 工作流结构

```
基础生成工作流 → VAE Decode → Image Upscale With Model → Save Image
                                    ↑
                          Load Upscale Model
```

#### 所需节点

| 序号 | 节点名称 | 功能 |
|-----|---------|------|
| 1 | 加载模型（Load Checkpoint） | 加载模型 |
| 2 | CLIP文本编码器（CLIP Text Encode） | 提示词 |
| 3 | 空Latent图像（Empty Latent Image） | 设置基础尺寸 |
| 4 | K采样器（KSampler） | 采样器 |
| 5 | VAE解码（VAE Decode） | 解码 |
| 6 | Load Upscale Model | 加载放大模型 |
| 7 | Image Upscale With Model | 放大图像 |
| 8 | 保存图像（Save Image） | 保存 |

#### 详细搭建步骤

1. **搭建基础文生图工作流**
   - 参考 案例1.1 搭建完整工作流
   - 设置基础尺寸为 512x512

2. **添加放大模型节点**
   - 双击空白处
   - 搜索 `Load Upscale Model`
   - 选择已下载的放大模型（如 RealESRGAN_x4plus）

3. **添加图像放大节点**
   - 双击空白处
   - 搜索 `Image Upscale With Model`
   - 连接 Load Upscale Model 的输出到 upscale_model 输入
   - 连接 VAE Decode 的输出到 image 输入

4. **连接保存节点**
   - 将 Image Upscale With Model 的输出连接到 Save Image

#### 参数配置

**Image Upscale With Model 参数：**

| 参数 | 说明 | 推荐值 |
|-----|------|-------|
| upscale_model | 放大模型 | Real-ESRGAN x4plus |
| image | 输入图像 | 来自 VAE Decode |

**放大倍数说明：**

| 模型 | 放大倍数 | 512x512 → 结果 |
|-----|---------|---------------|
| Real-ESRGAN x4plus | 4x | 2048x2048 |
| 4x-UltraSharp | 4x | 2048x2048 |

### 步骤 3: 方法二 - Hires Fix（高清修复）

#### 什么是 Hires Fix？

Hires Fix 是一种两步法高清修复技术：
1. **第一步：** 在低分辨率下生成基础图像
2. **第二步：** 放大并在高分辨率下重新采样，增强细节

#### 工作流结构

```
KSampler (第一次) → Latent Upscale → KSampler (第二次) → VAE Decode → Save Image
```

#### 所需节点

| 序号 | 节点名称 | 功能 |
|-----|---------|------|
| 1 | 加载模型（Load Checkpoint） | 加载模型 |
| 2 | CLIP文本编码器（CLIP Text Encode） (x2) | 正负提示词 |
| 3 | 空Latent图像（Empty Latent Image） | 设置基础尺寸 |
| 4 | K采样器（KSampler） (第一次) | 基础生成 |
| 5 | Latent Upscale | Latent 放大 |
| 6 | K采样器（KSampler） (第二次) | 细节增强 |
| 7 | VAE解码（VAE Decode） | 解码 |
| 8 | 保存图像（Save Image） | 保存 |

#### 详细搭建步骤

1. **搭建基础文生图工作流**
   - 参考 案例1.1
   - 设置基础尺寸为 512x512

2. **添加 Latent Upscale 节点**
   - 双击空白处
   - 搜索 `Latent Upscale`
   - 连接第一个 KSampler 的输出到 samples 输入

3. **添加第二个 KSampler**
   - 复制第一个 KSampler 节点（选中后 Ctrl+C, Ctrl+V）
   - 连接 Latent Upscale 的输出到 latent_image 输入
   - 连接相同的 MODEL、positive、negative

4. **修改连接**
   - 将 VAE Decode 的输入改为第二个 KSampler 的输出

#### 参数配置

**第一次 KSampler（基础生成）：**

| 参数 | 值 | 说明 |
|-----|---|------|
| steps | 15-20 | 基础生成步数可稍低 |
| denoise | 1.0 | 文生图固定为 1.0 |
| 尺寸 | 512x512 | 在 Empty Latent Image 设置 |

**Latent Upscale：**

| 参数 | 值 | 说明 |
|-----|---|------|
| upscale_method | nearest-exact | 放大方法 |
| width | 1024 | 目标宽度 |
| height | 1024 | 目标高度 |
| crop | disabled | 裁剪 |

**第二次 KSampler（细节增强）：**

| 参数 | 值 | 说明 |
|-----|---|------|
| steps | 15-20 | 增强步数 |
| denoise | 0.3-0.5 | 关键参数！ |

### 步骤 4: 理解 Hires Fix 中的 denoise

**第二次 KSampler 的 denoise 是 Hires Fix 的关键参数！**

#### denoise 在 Hires Fix 中的作用

| denoise | 效果 | 适用场景 |
|---------|------|---------|
| 0.2-0.3 | 轻微变化，保持原图细节 | 保留更多原始特征 |
| 0.3-0.5 | 中等变化，增加细节 | 推荐范围 |
| 0.5-0.7 | 明显变化，可能改变构图 | 创意效果 |
| 0.7+ | 大幅变化，可能失真 | 不推荐 |

#### denoise 选择建议

| 目标分辨率 | 推荐 denoise | 说明 |
|-----------|-------------|------|
| 1024x1024 | 0.35-0.45 | 2倍放大 |
| 1536x1536 | 0.40-0.50 | 3倍放大 |
| 2048x2048 | 0.45-0.55 | 4倍放大 |

### 步骤 5: 生成高清图像

1. 确认所有节点连接正确
2. 检查参数设置
3. 点击 **Queue Prompt**
4. 等待生成完成（Hires Fix 需要两次采样）
5. 查看最终高清图像

- 第二次采样：steps=20, denoise=0.4

2. Latent Upscale 放大到 1024x1024

- 可选第三步：模型放大到 4096

1. 生成 512x512 基础图像
2. 第一次 Hires Fix 到 1024x1024

**预期效果：** 超高清图像，细节丰富

## ❓ 常见问题（FAQ）

### Q1: 放大后图像模糊怎么办？

**问题描述：** 使用放大模型后，图像变模糊或细节丢失。

**可能原因：**
1. 放大模型不适合该类型图像
2. 原图质量不佳
3. 放大倍数过大

**解决方案：**

| 方案 | 操作 | 效果 |
|-----|------|------|
| 方案1 | 更换放大模型 | 尝试 4x-UltraSharp |
| 方案2 | 使用 Hires Fix | 重新采样增强细节 |
| 方案3 | 减小放大倍数 | 分步放大 |
| 方案4 | 提高原图质量 | 使用更好的基础生成参数 |

**放大模型选择建议：**

| 图像类型 | 推荐模型 |
|---------|---------|
| 照片 | Real-ESRGAN x4plus |
| 动漫/插画 | 4x-UltraSharp |
| 通用 | Real-ESRGAN x4plus |

### Q2: Hires Fix 后细节丢失或变模糊怎么办？

**问题描述：** 使用 Hires Fix 后，图像细节反而变少或变模糊。

**可能原因：**
1. 第二次 denoise 过低
2. 采样步数不足
3. 放大方法不合适

**解决方案：**

| 方案 | 操作 | 说明 |
|-----|------|------|
| 方案1 | 提高第二次 denoise | 从 0.3 提高到 0.4-0.5 |
| 方案2 | 增加采样步数 | steps 提高到 25-30 |
| 方案3 | 更换放大方法 | 使用 bilinear 或 bicubic |
| 方案4 | 分步放大 | 不要一次放大太多 |

**denoise 调整建议：**
- 细节丢失：提高 denoise（+0.1）
- 细节变化太大：降低 denoise（-0.1）

### Q3: 显存不足（Out of Memory）怎么办？

**问题描述：** 高清修复时出现显存不足错误。

**可能原因：**
1. 目标分辨率过高
2. 显存太小
3. 其他程序占用显存

**解决方案：**

| 方案 | 操作 | 效果 |
|-----|------|------|
| 方案1 | 降低目标分辨率 | 从 2048 降到 1024 |
| 方案2 | 使用低显存模式 | `--lowvram` 启动 |
| 方案3 | 分步放大 | 512→1024→2048 |
| 方案4 | 关闭其他程序 | 释放显存 |
| 方案5 | 使用模型放大 | 显存消耗更低 |

**分步放大策略：**
1. 先放大到 1024x1024
2. 保存图像
3. 清除工作流
4. 将 1024 图像作为输入继续放大

### Q4: Hires Fix 和模型放大哪个效果更好？

**问题描述：** 不确定应该使用哪种方法。

**对比分析：**

| 对比项 | 模型放大 | Hires Fix |
|-------|---------|-----------|
| 速度 | 快（几秒） | 慢（几十秒） |
| 显存 | 低 | 高 |
| 细节 | 增强 | 新增 |
| 质量 | 好 | 更好 |
| 适用 | 已有图像放大 | 从头生成高清 |

**选择建议：**

| 场景 | 推荐方法 |
|-----|---------|
| 快速放大已有图像 | 模型放大 |
| 生成高质量新图像 | Hires Fix |
| 显存有限 | 模型放大 |
| 追求最佳效果 | Hires Fix + 模型放大组合 |

### Q5: 如何实现 4K 图像生成？

**问题描述：** 想要生成 3840x2160 或更高分辨率的图像。

**解决方案：**

**方法一：分步 Hires Fix**
1. 512 → 1024（第一次 Hires Fix）
2. 1024 → 2048（第二次 Hires Fix）
3. 2048 → 4096（模型放大）

**方法二：Hires Fix + 模型放大**
1. 512 → 1024（Hires Fix）
2. 1024 → 4096（模型放大 4x）

**注意事项：**
- 4K 图像需要大量显存（建议 12GB+）
- 分步处理更稳定
- 可能需要较长时间
