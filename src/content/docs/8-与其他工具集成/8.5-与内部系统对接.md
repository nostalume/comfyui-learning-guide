# 8.5 与内部系统对接

> **本文承接：** [5.4 API 调用](../5-自动化与批量生成/5.4-API调用.md) 给了那条「提交 → 等 → 取图」的基本回路，[5.5 自动化流水线](../5-自动化与批量生成/5.5-自动化流水线.md) 让这条回路能跑一千遍不出事故。但这两篇的主角始终是**你自己的脚本**。当需求从「我要一批图」变成「**别的系统要调我的图**」时，脚本就不再够用 —— 你要交出去的是一个**服务**。

## 8.5.1 从脚本到服务，多了三件事

**脚本的调用者是你自己，服务的调用者是不可信、不可控的外部系统。** 这一句话推出了全部差别：

| 因为 | 所以必须多出 |
|------|-------------|
| 调用者不是你，看不懂节点编号 | **接口契约** —— 对外只暴露业务语义，不暴露工作流内部结构 |
| 调用者不可信，可能写错也可能滥用 | **身份与配额** —— 鉴权、限流、输入校验、审计 |
| 调用者随时在，而你的机器会重启 | **可用性** —— 任务不丢、进度可查、多用户互不阻塞 |

本节余下部分就按这三件事展开。底层端点、客户端实现、WebSocket 回调机制**不再重复**，一律见 [5.4 API 调用](../5-自动化与批量生成/5.4-API调用.md)。

### 官方已经标准化了一部分：Comfy API v2 与官方 SDK

上面三件事里，**「接口契约」与「可用性」的一部分，官方已经做成产品了**。所以动手自建之前，先判断自己在哪一侧：

| 你的处境 | 该走哪条路 |
|----------|-----------|
| 工作流跑在**你自己的机器**上，只是要给别人调 | **本篇的网关方案** —— 内置 API 没有身份也没有配额，这两件事必须你自己补 |
| 不想自己准备显卡、也不想运维，愿意把算力交给托管环境 | **Comfy API v2 + 官方 SDK** —— 提交、轮询、取输出、断线重连、幂等重试、输出 URL 的寿命，官方都替你处理了 |
| 只需要调合作方模型（Flux、Veo、Gemini、Kling 等），不需要自己那张图 | **Comfy Router** —— 但它**尚未正式可用**，先读官方的[限制说明](https://docs.comfy.org/development/comfy-router/limitations) |

v2 的骨架只有三条：

- **三个运行面同一套 API，只换 base URL**：Comfy Cloud（`https://cloud.comfy.org`）、你在 Developer Platform 上的专属部署（`https://{deployment}.run.comfy.app`）、自托管经 `comfy-api-proxy`（`http://127.0.0.1:8189`）
- **认证统一**：`Authorization: Bearer <api-key>`；官方 SDK 里由 `Comfy(api_key=...)` 加环境变量 `COMFY_BASE_URL` 决定连哪一面
- **提交的仍然是那份「API 格式」工作流 JSON** —— 与本篇一直在说的是同一份东西

> 💡 **它替代不了本篇。** v2 解决的是「提交与取回」，**不解决业务语义**：调用方仍然不该知道节点编号（[8.5.2](#852-接口契约网关该暴露什么)），租户、配额与审计仍然是你的事（[8.5.3](#853-身份与配额谁在用能用多少)）。**它换掉的只是最底下那条链路。**

> ⚠️ **v2 与官方 SDK 都还是 Beta**（`0.1.x` / `0.4.0`），接口形状可能变；而内置 API 反而更稳。最小示例与运行面细节见 [A8.3 / A8.4](../附录/A8-官方文档与公共API速查.md)。

## 8.5.2 接口契约：网关该暴露什么

### 为什么不直接暴露 ComfyUI 的 `/prompt`

ComfyUI 的 `/prompt` 接收的是**整份工作流 JSON**。把它原样开放出去有三个问题：

- **泄漏实现**：调用方必须知道 `"6": {"inputs": {"text": ...}}` 这种节点编号。工作流一改，所有调用方全挂
- **无法校验**：任何字段都能被替换，包括你精心调好的模型名与采样器
- **没有版本**：接口没有版本概念，改动无法灰度

所以中间要有一层**网关**：对内持有工作流模板，对外只暴露业务参数。**节点编号只存在于网关内部**，这是这一层存在的根本理由。

### 三个端点就够

| 端点 | 方法 | 作用 |
|------|------|------|
| `/api/generate` | POST | 提交生成请求，立刻返回任务 ID |
| `/api/status/{task_id}` | GET | 查询任务状态 |
| `/api/result/{task_id}` | GET | 取回图像 |

> 💡 **为什么是「立刻返回任务 ID」而不是「等出图再返回」？** 一次生成要几十秒到几分钟，同步等待会让调用方超时、让 HTTP 连接长期挂住。异步任务语义是所有长耗时服务的通用做法 —— 底层机制（任务 ID 从哪来、怎么知道跑完了）见 [5.4 API 调用](../5-自动化与批量生成/5.4-API调用.md)。

### FastAPI 网关完整实现

**FastAPI** 是一个 Python 的 Web 框架 —— 用几十行就能把上面那三个端点实现出来。下面是一份完整实现；**不必逐行读**，看每个函数开头的注释知道它在做什么即可。

```python
from fastapi import FastAPI, HTTPException, Header, Depends
from fastapi.responses import Response
from pydantic import BaseModel, Field
import json
import os
import requests

COMFYUI = "http://127.0.0.1:8188"
TEMPLATE_DIR = "./templates"

# 租户令牌。生产环境应放进环境变量或密钥服务，不要写进代码
API_KEYS = {"team-a-key": "team-a", "team-b-key": "team-b"}

app = FastAPI(title="ComfyUI 生成服务", version="1.0")


class GenerateRequest(BaseModel):
    """对外的接口形状 —— 只有业务参数，没有节点编号"""
    template: str = Field("txt2img", description="模板名，由网关决定对应哪份工作流")
    prompt: str = Field(..., max_length=2000)
    negative_prompt: str = Field("", max_length=2000)
    width: int = Field(512, ge=64, le=2048)
    height: int = Field(512, ge=64, le=2048)
    steps: int = Field(20, ge=1, le=100)
    seed: int = Field(-1, description="-1 表示随机")


def auth(authorization: str = Header(default="")) -> str:
    """鉴权：把 Bearer 令牌换成租户名"""
    token = authorization.removeprefix("Bearer ").strip()
    tenant = API_KEYS.get(token)
    if not tenant:
        raise HTTPException(status_code=401, detail="invalid api key")
    return tenant


def load_template(name: str, params: dict) -> dict:
    """取模板并把业务参数注入到**网关自己声明的**节点上

    节点 ID 在这里写死一次（按你导出的 API 格式工作流填），
    调用方永远看不到它们。
    """
    path = os.path.join(TEMPLATE_DIR, f"{name}.json")
    if not os.path.exists(path):
        raise HTTPException(status_code=404, detail=f"unknown template: {name}")

    with open(path, encoding="utf-8") as f:
        workflow = json.load(f)

    injection = {
        "6": {"text": params["prompt"]},                       # 正向提示词
        "7": {"text": params["negative_prompt"]},              # 负向提示词
        "5": {"width": params["width"], "height": params["height"]},
        "3": {"steps": params["steps"], "seed": params["seed"]},
    }
    for node_id, fields in injection.items():
        if node_id in workflow:
            workflow[node_id]["inputs"].update(fields)
    return workflow


@app.post("/api/generate")
def generate(req: GenerateRequest, tenant: str = Depends(auth)):
    workflow = load_template(req.template, req.model_dump())

    r = requests.post(f"{COMFYUI}/prompt", json={"prompt": workflow}, timeout=30)
    if r.status_code != 200:
        raise HTTPException(status_code=502, detail=r.text)

    return {"task_id": r.json()["prompt_id"], "status": "pending", "tenant": tenant}


@app.get("/api/status/{task_id}")
def status(task_id: str, tenant: str = Depends(auth)):
    history = requests.get(f"{COMFYUI}/history/{task_id}", timeout=10).json()
    if task_id not in history:
        return {"status": "pending"}
    st = history[task_id].get("status", {}).get("status_str", "unknown")
    return {"status": st}


@app.get("/api/result/{task_id}")
def result(task_id: str, tenant: str = Depends(auth)):
    history = requests.get(f"{COMFYUI}/history/{task_id}", timeout=10).json()
    if task_id not in history:
        raise HTTPException(status_code=202, detail="still running")

    for output in history[task_id].get("outputs", {}).values():
        for img in output.get("images", []):
            data = requests.get(
                f"{COMFYUI}/view",
                params={
                    "filename": img["filename"],
                    "subfolder": img.get("subfolder", ""),
                    "type": "output",
                },
                timeout=60,
            ).content
            return Response(content=data, media_type="image/png")

    raise HTTPException(status_code=404, detail="no image in result")
```

启动：

上面那份代码只是一段**定义**，还得有人把它跑起来、接住进来的 HTTP 请求 —— **uvicorn** 就是这个角色（Python 的 ASGI 服务器，也是 FastAPI 官方推荐的运行方式）：

```bash
uvicorn gateway:app --host 0.0.0.0 --port 8000
```

### 版本化

对外接口一旦有人用，就不能随意改。最低成本的版本化是**放在路径里**：

```text
/api/v1/generate
/api/v1/status/{task_id}
```

新增字段是兼容的，删除或改语义才需要开 `/api/v2`。模板名与业务参数属于契约的一部分，**不要**把节点编号放进契约。

## 8.5.3 身份与配额：谁在用、能用多少

### 鉴权

上一节的 `Depends(auth)` 已经给出最小实现。要点只有两条：

- 令牌→租户的映射放在**服务端**，租户只拿到令牌本身
- 每个请求都带上租户，写进日志与台账 —— 否则事后无法回答「这张图是谁要的」

### 限流

限流的目的是**保护 GPU**，不是惩罚用户。ComfyUI 默认串行执行，排队过长时新请求只会等到超时。

```python
import time
from collections import defaultdict, deque

WINDOW = 60      # 秒
LIMIT = 60       # 每窗口每租户的请求数
_calls: dict[str, deque] = defaultdict(deque)


def rate_limit(tenant: str) -> None:
    now = time.time()
    q = _calls[tenant]
    while q and now - q[0] > WINDOW:
        q.popleft()
    if len(q) >= LIMIT:
        raise HTTPException(status_code=429, detail="rate limit exceeded")
    q.append(now)
```

在 `generate` 开头调用 `rate_limit(tenant)` 即可。单进程内存计数就够用；多实例部署时要换成 Redis 计数器。

### 输入校验与审计

| 项 | 做法 |
|------|------|
| 参数范围 | 用 `Field(ge=..., le=...)` 声明，越界直接 422，**别让它进到 GPU 才报错** |
| 模板白名单 | 模板名必须是服务端已知的名字，不接受路径拼接（防目录穿越） |
| 提示词长度 | 设上限，避免超长提示词拖垮 CLIP 编码 |
| 审计日志 | 记 `时间 / 租户 / 任务 ID / 模板 / 参数 / 状态`。要能凭它重跑出同一张图 |

审计日志与 [5.5 自动化流水线](../5-自动化与批量生成/5.5-自动化流水线.md) 的任务台账是同一张表的两面：**台账服务你的排查，审计服务"谁用了多少"**。团队规模不大时共用一张表即可。

## 8.5.4 可用性：多用户与规模

### 先接受一个约束

ComfyUI **默认串行执行**任务（队列机制见 [5.2 队列管理](../5-自动化与批量生成/5.2-队列管理.md)）。你的网关并发再高，真正的瓶颈也在 GPU 上。所以扩容的方向不是「让网关收更多请求」，而是**让排队可控、让故障可查**。

### 三种扩容路径

| 路径 | 做法 | 适用 |
|------|------|------|
| **单实例 + 背压** | 网关限制在途任务数（如 2），超出的立刻返回「稍后重试」 | 团队内几人共用，最简单 |
| **多实例 + 负载均衡** | 起多个 ComfyUI（各自占一张卡或一份显存），网关轮询分发 | 有多张 GPU 时 |
| **消息队列解耦** | 请求进 Redis / RabbitMQ，worker 从队列取任务执行 | 需要削峰、任务不能丢 |

背压的最小实现是**限制在途任务数**：

```python
import threading

MAX_INFLIGHT = 2
_inflight = threading.Semaphore(MAX_INFLIGHT)

# generate 里：
if not _inflight.acquire(blocking=False):
    raise HTTPException(status_code=429, detail="busy, retry later")
try:
    ...
finally:
    _inflight.release()
```

> ⚠️ **并发度不要凭感觉调。** 并发跑多个任务会同时占用多份显存，反而更容易 OOM。显存账见 [7.5 显存优化](../7-性能优化与显存管理/7.5-显存优化.md)；`5.5` 也给了同样结论的脚本侧版本。

### 健康检查

负载均衡器需要一个探针，它必须**真的检查 ComfyUI**，而不是只回 200：

```python
@app.get("/healthz")
def healthz():
    try:
        requests.get(f"{COMFYUI}/queue", timeout=3)
        return {"gateway": "ok", "comfyui": "ok"}
    except requests.RequestException:
        raise HTTPException(status_code=503, detail="comfyui unreachable")
```

### 任务不丢

网关重启不应让在途任务消失。两条最低要求：

- 网关**提交前**先写一条台账（状态 `pending`），拿到 `prompt_id` 后回填
- 重启后用 `/history` 对账，把 `pending` 且实际已完成的补上

台账的表结构与操作见 [5.5 自动化流水线](../5-自动化与批量生成/5.5-自动化流水线.md)。

## 8.5.5 服务端的模板管理

网关需要按名字取模板，所以模板要有一份**程序可读的**登记。这与 [5.3 工作流复用](../5-自动化与批量生成/5.3-工作流复用.md) 讲的是同一份工作流 JSON，只是前者在界面上保存，这里在代码里存取。

```python
import json
import os
import time


class WorkflowTemplateManager:
    """工作流模板的存取与参数注入"""

    def __init__(self, template_dir: str = "./templates"):
        self.template_dir = template_dir
        os.makedirs(template_dir, exist_ok=True)

    def save(self, name: str, workflow: dict,
             description: str = "", params: dict | None = None) -> str:
        data = {
            "name": name,
            "description": description,
            "workflow": workflow,
            "params": params or {},
            "created_at": time.strftime("%Y-%m-%d %H:%M:%S"),
        }
        path = os.path.join(self.template_dir, f"{name}.json")
        with open(path, "w", encoding="utf-8") as f:
            json.dump(data, f, indent=2, ensure_ascii=False)
        return path

    def load(self, name: str) -> dict:
        path = os.path.join(self.template_dir, f"{name}.json")
        if not os.path.exists(path):
            raise FileNotFoundError(f"模板不存在: {name}")
        with open(path, encoding="utf-8") as f:
            return json.load(f)

    def list(self) -> list[dict]:
        out = []
        for filename in os.listdir(self.template_dir):
            if filename.endswith(".json"):
                with open(os.path.join(self.template_dir, filename),
                          encoding="utf-8") as f:
                    d = json.load(f)
                out.append({
                    "name": d.get("name", filename[:-5]),
                    "description": d.get("description", ""),
                    "created_at": d.get("created_at", ""),
                })
        return out

    def apply_params(self, name: str, params: dict) -> dict:
        """按字段名把参数写进模板（仅覆盖模板里已存在的字段）"""
        workflow = self.load(name)["workflow"]
        for key, value in params.items():
            for node in workflow.values():
                if "inputs" in node and key in node["inputs"]:
                    node["inputs"][key] = value
        return workflow
```

> 💡 **`apply_params` 按字段名注入，上一节的 `load_template` 按节点 ID 注入。** 前者适合模板结构统一、字段名不冲突时；后者更精确，适合模板里同一个字段名出现在多个节点的情况（如 `text` 同时出现在正负提示词节点）。服务端建议用后者 —— 把不确定性留在自己手里。

## 8.5.6 部署与网络

### 只监听内网

ComfyUI 的 API **没有身份概念**。任何能访问它的人都等于拿到了你的 GPU。所以：

```bash
# ComfyUI 只监听内网地址，网关才是对外入口
python main.py --listen 192.168.1.100 --port 8188
```

网关再通过 Nginx 对外暴露。

### Nginx 反向代理 + 基础认证

```nginx
server {
    listen 443 ssl;
    server_name comfy.example.com;

    auth_basic "ComfyUI Service";
    auth_basic_user_file /etc/nginx/.htpasswd;

    client_max_body_size 100M;          # 图生图要上传图片

    location / {
        proxy_pass http://127.0.0.1:8000;   # 指向网关，不是 ComfyUI
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;
    }
}
```

创建密码文件：

```bash
htpasswd -c /etc/nginx/.htpasswd admin
```

> ⚠️ `proxy_pass` 指向**网关（8000）**而不是 ComfyUI（8188）。直接反代 ComfyUI 会让上一节的全部努力失效 —— 调用方又能碰 `/prompt` 了。

### CORS

如果调用方是浏览器里的前端，需要 ComfyUI 允许跨域。启动参数与出处见 [5.4 API 调用](../5-自动化与批量生成/5.4-API调用.md)。更推荐的做法是**由网关统一处理 CORS**，ComfyUI 始终留在内网。

### 容器化

网关与 ComfyUI 可以分别打包成镜像，用同一个 `docker-compose` 起。注意 GPU 透传（`--gpus all`）与模型目录挂载 —— 模型通常有几个 GB 到几十 GB，**不要打进镜像**。

## 8.5.7 一个完整场景：电商产品图生成

业务侧的需求是「上传产品照片，得到一张带场景的产品图」。整条链路是这样的：

1. 业务系统调用网关的 `/api/generate`，模板名 `product-shot`，参数含产品图张数、风格
2. 网关取模板 → 上传产品图到 ComfyUI → 提交任务 → 返回 `task_id`
3. 业务系统轮询 `/api/status/{task_id}`，完成后用 `/api/result/{task_id}` 取图
4. 全程记录到台账，业务侧凭 `request_id` 追溯

```python
import requests
import time

GATEWAY = "http://comfy.example.com/api/v1"
HEADERS = {"Authorization": "Bearer team-a-key"}


def generate_product_shot(product_id: str, style: str) -> str:
    """业务侧只需要知道模板名和风格 —— 不需要知道任何节点"""
    r = requests.post(
        f"{GATEWAY}/generate",
        headers=HEADERS,
        json={
            "template": "product-shot",
            "prompt": f"{style}, product photography, professional lighting",
            "negative_prompt": "blurry, low quality, distorted, watermark",
            "steps": 25,
            "seed": -1,
        },
        timeout=30,
    )
    r.raise_for_status()
    task_id = r.json()["task_id"]

    for _ in range(120):                      # 最多等 10 分钟
        s = requests.get(f"{GATEWAY}/status/{task_id}", headers=HEADERS).json()
        if s["status"] == "success":
            img = requests.get(f"{GATEWAY}/result/{task_id}", headers=HEADERS)
            path = f"./product_images/{product_id}.png"
            with open(path, "wb") as f:
                f.write(img.content)
            return path
        if s["status"] == "error":
            raise RuntimeError(f"生成失败: {task_id}")
        time.sleep(5)

    raise TimeoutError(f"超时: {task_id}")
```

这个例子的重点不在代码，而在**边界**：业务侧只认得「模板名 + 风格」，网关承担了全部与 ComfyUI 相关的知识。

## 8.5.8 常见问题

<details>
<summary>❓ 接口调用超时怎么办？</summary>

先分清是哪一段超时：

1. **提交就超时** —— ComfyUI 没起或地址不对。直接 `curl http://127.0.0.1:8188/queue` 验证
2. **查询状态一直 pending** —— 队列积压。看 `/queue` 的 `queue_pending` 长度
3. **单张图时间过长** —— 分辨率和步数决定的，不是接口问题。优化见 [7.3 推理加速](../7-性能优化与显存管理/7.3-推理加速.md)

正确做法是**不要让接口等出图**：提交后立刻返回 `task_id`，由业务侧轮询或订阅（机制见 [5.4 API 调用](../5-自动化与批量生成/5.4-API调用.md)）。

</details>

<details>
<summary>❓ 如何处理大量并发请求？</summary>

按代价从低到高：

1. **背压**：限制在途任务数，超出直接返回 429 —— 大多数团队只需要这一步
2. **消息队列**：请求进 Redis / RabbitMQ，worker 逐个取。任务不丢、可削峰
3. **多实例 + 负载均衡**：有多张 GPU 时才有意义

⚠️ 不要靠「把并发调大」解决 —— ComfyUI 串行执行，并发只是把压力转移到显存上。

</details>

<details>
<summary>❓ 工作流执行失败如何排查？</summary>

```python
history = requests.get(f"{COMFYUI}/history/{prompt_id}").json()
messages = history[prompt_id].get("status", {}).get("messages", [])
print(messages)
```

常见原因：模型文件不存在、节点参数越界、显存不足（见 [7.5 显存优化](../7-性能优化与显存管理/7.5-显存优化.md)）。

定位手段：把出错的模板**导回 ComfyUI 界面手动跑一次** —— 界面会给出比 API 更清楚的报错。

</details>

<details>
<summary>❓ 如何保证生成结果可复现？</summary>

四件事同时做到才可复现：

- **固定种子**（`seed` 不要用 `-1`）
- **锁定模型版本**（同一个文件名不等于同一份权重，记录哈希更稳妥）
- **记录完整参数**（步数、CFG、采样器、分辨率，一个都不能漏）
- **记录节点包版本**（自定义节点升级会改变行为）

这四条正是任务台账要存的字段 —— 见 [5.5 自动化流水线](../5-自动化与批量生成/5.5-自动化流水线.md)。

</details>

<details>
<summary>❓ 业务系统不是 Python 写的，怎么接？</summary>

接口是标准 HTTP + JSON，**任何语言都能调**：

- Java / Go / Node.js / C#：直接用各自的 HTTP 客户端
- 低代码平台：用它的 HTTP 请求节点，把模板名与参数当表单字段
- 数据库直连场景：把台账表暴露给报表工具即可，不需要调接口

跨平台的关键是**接口稳定**：只要 `/api/v1` 的契约不变，内部换模型、换工作流都不影响调用方。

</details>
