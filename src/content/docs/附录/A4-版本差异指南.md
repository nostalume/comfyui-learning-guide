# A4 版本差异指南

> **适用版本：** ComfyUI 本体 `v0.37.x` / Comfy Desktop `v1.1.x`（两套版本号各自独立）
> **相关官方文档：** [桌面端](https://docs.comfy.org/installation/desktop/windows) | [便携版](https://docs.comfy.org/installation/comfyui_portable_windows) | [手动安装](https://docs.comfy.org/installation/manual_install) | [实例管理](https://docs.comfy.org/installation/desktop/usage/instance-management) | [实例设置](https://docs.comfy.org/installation/desktop/usage/manage)
>
> **用途：** 查阅型附录 —— 三条安装路径的能力对照、目录差异与互相迁移。
> **首次安装请走正篇：** [1.1 Windows 安装](../1-概述与安装部署/1.1-Windows安装.md) / [1.2 macOS 安装](../1-概述与安装部署/1.2-macOS安装.md)；系统要求与启动参数见 [A6 安装部署参考](./A6-安装部署参考.md)。本页不重复这两项。

## A4.1 先纠正一个说法：不是「两个版本」，而是「三条安装路径」

网上常见「GitHub 版 vs 桌面端」的二分法，那是 2024 年的口径。现在官方给的是**三条路**，而且**程序本体是同一份源码** —— 差别只在「谁帮你把 Python 环境和依赖装好」以及「文件放在哪」：

| 路径 | 一句话 | 正篇 |
|------|--------|------|
| **Comfy Desktop** | 装一个多实例管理器，由它创建、管理、更新若干彼此独立的 ComfyUI | [1.1.3](../1-概述与安装部署/1.1-Windows安装.md#113-方式一comfy-desktop推荐) |
| **Windows 便携版** | 一个自带 Python 的压缩包，解压后双击 `.bat` | [1.1.4](../1-概述与安装部署/1.1-Windows安装.md#114-方式二windows-便携版) |
| **手动安装** | `git clone` 源码 → 自建虚拟环境 → `python main.py` | [1.1.5](../1-概述与安装部署/1.1-Windows安装.md#115-方式三手动安装开发者路线) |

> ⚠️ **两套版本号，别对号入座：** ComfyUI 本体的版本号（`v0.37.x`）与 Comfy Desktop 的版本号（`v1.1.x`）**各自独立**。桌面端是启动器，它管理的每个实例各自装一个 ComfyUI 版本 —— 所以「桌面端版本号比 ComfyUI 低」是正常的。

## A4.2 我该选哪条

三个问题就能定下来：

| 你的情况 | 选 |
|----------|-----|
| 只想出图，不想碰命令行 | **Comfy Desktop** |
| 想让别的程序调它（脚本 / API / 自动化） | **手动安装** |
| 没有管理员权限，或想随身带在 U 盘上 | **Windows 便携版** |
| 机器上已经有一套自己配好的 ComfyUI | 不用重装 —— 用桌面端的 `Add Existing Instance` 把它纳管进来 |

三条路**不互斥**，可以同时装。但**模型目录各在一处**，这是三个世界之间最容易踩的坑（见 [2.1 项目结构与模型存放](../2-模型体系与管理/2.1-项目结构与模型存放.md)）。

## A4.3 能力对照

| 能力 | Comfy Desktop | Windows 便携版 | 手动安装 |
|------|---------------|----------------|----------|
| 上手难度 | ⭐ 一键安装 | ⭐⭐ 解压即用 | ⭐⭐⭐⭐ 需自配环境 |
| 命令行参数 | ✅ 实例 `Manage` → `Startup Args` → `Startup Arguments` | ✅ 编辑对应 `.bat`，在 `main.py` 后追加 | ✅ 终端里直接拼 |
| 自定义节点 | ✅ 内置管理器（按实例的「安全级别」放行） | ✅ 手动放进 `custom_nodes/` | ✅ 同左 |
| 多版本并存 | ✅ 多实例，Python 环境彼此隔离 | ✅ 解压多份 | ✅ 克隆多份 |
| 自动更新 | ✅ 内置（`Stable` / `Latest on GitHub` 两个通道） | ✅ `update/` 目录下的脚本 | ❌ 自己 `git pull` |
| 快照回滚 | ✅ 仅 **Standalone** 实例支持 | ❌ | ❌ |
| 本地 API | ✅ 实例端口（默认 8188） | ✅ | ✅ |
| 显存模式等启动开关 | ✅ 同左（走启动参数） | ✅ | ✅ |
| 纳管已有安装 | ✅ `Add Existing Instance`（可识别便携版与 git 克隆） | — | — |

> 📌 **「桌面端不支持命令行参数」是过时说法。** 新版 Comfy Desktop 在每个实例的 `Manage` 面板里有 `Startup Args` 标签，`Startup Arguments` 一栏可以填 `--listen`、`--lowvram` 等任意 CLI 参数，点旁边的齿轮图标还能按分类勾选。官方参数表的权威来源仍是源码 [`comfy/cli_args.py`](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/cli_args.py)。

## A4.4 目录结构差异

**手动安装 / 便携版的目录结构见 [A6.3](./A6-安装部署参考.md#a63-目录结构)。** 这里只讲桌面端为什么不一样。

Comfy Desktop 把「启动器」和「每个实例」分开管理，路径**不在程序目录下**：

| 内容 | Windows | macOS |
|------|---------|-------|
| 各个实例 | `%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Installs` | `~/ComfyUI-Installs` |
| 共享模型与输入/输出 | `%LOCALAPPDATA%\Comfy-Desktop\ComfyUI-Shared` | `~/ComfyUI-Shared` |
| 设置与安装记录 | `%APPDATA%\Comfy Desktop` | `~/Library/Application Support/Comfy Desktop` |
| 日志 | `%APPDATA%\Comfy Desktop\logs` | `~/Library/Logs/Comfy Desktop` |

> 💡 早期版本把实例装在 `%USERPROFILE%\ComfyUI-Installs` / `%USERPROFILE%\ComfyUI-Shared`（macOS 同路径）。找不到时，两个位置都看一眼。
>
> 💡 **一个实例内部长什么样：** 每个实例是一套自包含的 ComfyUI —— 里面有程序本体（含 `main.py`）、自己的 Python 环境（`standalone-env`）和自己的 `custom_nodes/`。所以「切换实例」= 切换一整套环境，互不干扰。

## A4.5 模型放哪里

| 路径 | 模型根在哪 |
|------|-----------|
| **手动安装** | `<ComfyUI 目录>/models/` |
| **Windows 便携版** | `<便携包目录>/ComfyUI/models/` |
| **Comfy Desktop** | `ComfyUI-Shared/models/`（所有实例共用），**不是**程序目录下 |

桌面端比另外两条路多一层概念：**「共享」**。所有实例默认都扫描共享模型目录，标记为 **Primary** 的那个还负责接收新下载的模型。想给某个实例单独加模型目录，去它的 `Manage` → `Storage` → `Model Directories`。

子文件夹怎么分、怎么反查自己机器的实际路径，见 [2.1 项目结构与模型存放](../2-模型体系与管理/2.1-项目结构与模型存放.md)。

## A4.6 互相迁移

### 从便携版 / 手动安装 → Comfy Desktop

**不用复制任何文件。** 桌面端可以直接纳管一套已经配好的 ComfyUI：

1. Dashboard → `New Instance` → `Add Existing Instance`
2. `Browse` 选中你的 ComfyUI 目录（含 `main.py` 的那一层；便携版通常是包内的 `ComfyUI/` 子目录）
3. 它会自动探测安装类型（便携版认 `standalone-env` + `ComfyUI/main.py`；git 克隆认 `models/`、`user/`、`.venv`）与 Python 环境路径，确认后即可

> ⚠️ 这种方式纳管进来的是 **Tracked** 实例：**没有自动更新、也不支持快照**，版本仍由你自己用 `git pull` 或便携版的更新脚本管理。要享受自动更新与快照，得新建 **Standalone** 实例。

### 从 Comfy Desktop → 便携版 / 手动安装

把共享模型目录整体搬过去即可：

```bash
# 桌面端的共享模型库 → 目标安装的 models/
cp -r "<ComfyUI-Shared>/models/." "<目标 ComfyUI 目录>/models/"
```

- 只搬 `models/` 下你实际要用的子目录（`checkpoints`、`lora` …），整库复制通常几十到几百 GB
- 桌面端的 `custom_nodes/` 在**各实例内部**，不在共享目录；需要的话从实例目录里单独取
- 桌面端实例里的工作流存在实例的 `user/` 下，屏幕上的导出更省事：工作流直接 `Export` 成 `.json`

## A4.7 常见问题

### Q1：模型放进桌面端了，下拉框里还是空的？

**原因：** 放在实例自己的 `ComfyUI/models/` 里，但该实例又开着「包含共享目录」。

**解决：** 桌面端的模型**优先放共享目录** `ComfyUI-Shared/models/`；放实例目录的话，去 `Manage` → `Storage` 确认 `Include Shared Directories` 与 `Model Directories` 的实际取值。改完**必须重启 ComfyUI**。

### Q2：手动安装后启动报错找不到模型？

**原因：** 模型根是 `<ComfyUI 目录>/models/`，不是别的地方。

**解决：** 确认模型放在 `<含 main.py 的那一层>/models/<对应子目录>/`；文件名不要含特殊字符；确认下载完整（半途中断的文件常常损坏）。

### Q3：桌面端怎么装自定义节点？

走界面里的节点管理器（默认 `Standard` 安全级别，只允许已注册的节点包）。要装注册表之外的，去 `Manage` → `Startup Args` 调 `Manager Security Level`，但官网明确提示：**只有在 `--listen` 未开启、本机可达的情况下才该放宽**。

### Q4：怎么确认自己用的是哪条路？

| 看到什么 | 就是哪条路 |
|----------|-----------|
| 桌面快捷方式叫 **Comfy Desktop**，进去先看到实例卡片列表 | Comfy Desktop |
| 目录里有 `python_embeded/` 和 `run_nvidia_gpu.bat` | Windows 便携版 |
| 目录里有 `.git/`，靠 `python main.py` 启动 | 手动安装 |

### Q5：两条路能同时装吗？

可以，互不影响。**但别让它们抢同一个端口** —— 桌面端实例端口冲突有 `If Port is Busy` 策略（`Ask what to do` / `Use next available port`），手动装的那份用 `--port` 显式指定即可。
