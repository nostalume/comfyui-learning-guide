# A7 如何读本文档

> **这篇写给谁：** 所有读者。特别是**不写代码**、但材料从第 5 章起会给出 Python 脚本的人。
> **这篇回答什么：** 本材料假设你会什么；遇到方框里的内容该怎么看；读不懂时去哪。

---

## A7.1 本材料假设你会什么

写清楚假设，是为了让**不符合假设的人知道去哪补**，而不是卡在某一页不动。

| 假设 | 到什么程度 | 不会的话 |
|------|-----------|---------|
| **会在终端里执行命令** | 知道"终端"是什么，能把一行命令粘进去回车 | 看 [1.1 Windows 安装](../1-概述与安装部署/1.1-Windows安装.md) 或 [1.2 macOS 安装](../1-概述与安装部署/1.2-macOS安装.md) 的"打开终端"一节 |
| **能读懂 20 行左右的 Python** | 知道变量、函数调用、字典是什么，不要求会自己写 | 见下面 A7.3 —— 读代码有三个层次，**不一定需要全懂** |
| **看得懂 JSON 的键值结构** | 知道 `"key": value` 是一组"名字 → 内容" | [1.4 工作流保存加载分享](../1-概述与安装部署/1.4-工作流保存加载分享.md) 里讲过工作流 JSON 长什么样 |
| **知道自己电脑的显卡与显存** | 大概知道型号和几 GB | 见 [7.1 生成速度 Benchmark](../7-性能优化与显存管理/7.1-生成速度benchmark.md) |

> **本材料不假设你会：** 写 Python、配数据库、用 Docker、搭服务器。
> 这些工具在第 5、8、9 章出现时，都会先说明"为什么需要它"，再给命令。

## A7.2 方框里的内容分三种，别当成一种

材料里所有灰底方框都是代码围栏，但它们**是三类不同的东西**。分不清会出两种错：把"示意"当命令去敲；或把"命令"当示意，以为不用执行。

### 命令 —— 照着敲

行首是程序的命令名，通常配 `bash` / `powershell` 标记。

```bash
python main.py --listen 0.0.0.0 --port 8188
```

看到这种，就是**可以复制到终端里运行**的。

### 代码 —— 要读懂，不一定要敲

配 `python` / `json` 等标记，是要展示"程序怎么做这件事"。

```python
result = client.queue_prompt(workflow)      # 把工作流交给 ComfyUI
history = client.wait_for_completion(result["prompt_id"])   # 等它跑完
```

看不懂语法时，**先看行尾的中文注释** —— 它写的就是这一行在做什么。注释连起来读，就是这段程序的流程。

### 排版示意 —— **不是命令，不要执行**

这一类最容易误读。它只是**用等宽的方框把格式对齐**，好让你看清楚结构。典型是目录树、命名模板、提交信息模板。

```text
ComfyUI/
├── models/          # 模型都放这里
│   ├── checkpoints/ # 主模型
│   └── loras/       # LoRA
```

`├──` 不是命令，是树枝符号。方框里写的是**你硬盘上长什么样**，不是**你要敲什么**。

```text
[基础模型]_[风格]_[版本].safetensors
sd15_realistic_v5.safetensors
```

这是**命名格式**：上面一行是格式，方括号里是占位符；下面一行是照这个格式起出来的真实名字。

### 怎么快速分辨

| 你看到 | 判断 | 该做什么 |
|--------|------|---------|
| 行首是 `git` / `pip` / `python xxx.py` / `docker` | 命令 | 可敲 |
| 行首是 `import` / `def` / `class` / `@app.` | 代码 | 读注释 |
| 有 `├──` / `└──` / `│` | 目录结构 | 只读 |
| 有 `[中文字]` 占位符、或 `feat:` `fix:` 开头 | 格式模板 | 只读 |
| 以 `{` 开头、成对出现 | JSON 数据 | 只读 |

## A7.3 读代码的三个层次

材料里的代码只需要读到第一层或第二层，**没有一处要求你能自己写出来**。

1. **读懂注释**：行尾 `#` 后面的中文就是这行的作用。只读注释通常就够。
2. **读懂流程**：把注释按顺序连起来 —— "先做什么、再做什么、最后得到什么"。这就是这段程序在讲的事。
3. **读懂语法**：变量、函数、类型。**只有想改这段代码时才需要。**

如果你卡在第 3 层，说明你要动手改了 —— 这时的正路不是死磕，是去对应的主线篇目：
自动化脚本看 [5.4 API 调用](../5-自动化与批量生成/5.4-API调用.md)，跑批量任务看 [5.5 自动化流水线](../5-自动化与批量生成/5.5-自动化流水线.md)，
把服务交给别人调用看 [8.5 与内部系统对接](../8-与其他工具集成/8.5-与内部系统对接.md)。

## A7.4 贯穿全书的几个约定

| 约定 | 含义 |
|------|------|
| `<...>` | **占位符** —— 尖括号里是说明，要换成你自己的值。如 `<ComfyUI 目录>`、`<你的模型文件名>` |
| 行尾 `#` 后的话 | 中文注释，解释这一行在做什么 |
| 一个方框里既有命令又有输出 | 以 `# 输出：` 这类注释分隔；**没有该注释时，方框内容都是要敲的命令** |
| `⚠️` | 容易踩的坑 |
| `💡` | 省事的技巧 |
| ❌ / ✅ | 错误做法 / 正确做法 |

> 早先的版本里有不少命令写死了作者本机的绝对路径（如 `E:\Dev\...`）。已逐步改为 `<ComfyUI 目录>` 这类占位符；若仍看到写死的路径，请按 `<ComfyUI 目录>` 理解。

## A7.5 读不懂时去哪

按顺序试这三条，别停在一页硬扛：

1. **回到本篇开头**：每篇都有「本文承接 / 本文引出」块，写明它接的是哪一篇的哪个概念。缺的那一块在那里。
2. **查术语**：[A1 术语对照表](./A1-术语对照表.md) 会告诉你这个术语**由哪一篇推导出来** —— 去那一篇，而不是背这张表。
3. **看案例**：每个主题多半有一篇对应的实战案例（章末有「对应练习」链接）。概念讲不通时，跟着案例做一遍往往就通了。
