## 0.3.1 同一件事，两种摆法

先看「用一句话生成一张图」这件事，在两个工具里各长什么样。

**WebUI：一张表，填完点一下。**

```text
+-- txt2img -------------------------------------------+
|  Prompt     [ a sunset over mountains            ]   |
|  Negative   [ blurry, low quality                ]   |
|  Width [512]   Height [512]   Steps [20]             |
|  Sampler [Euler a v]   CFG [7]   Seed [-1]   [dice]  |
|                                       [ Generate ]   |
+------------------------------------------------------+
```

**ComfyUI：一串框，被线连成一条链。**

```text
[Load Checkpoint] ---+
[CLIP: positive] -----+
[CLIP: negative] -----+--> [KSampler] --> [VAE Decode] --> [Save Image]
[Empty Latent Image] -+

[Queue Prompt]        <- 用这里让它跑起来
```

两张图讲的是**同一条流程**：给一段描述 → 让它算 → 得到一张图。区别在呈现方式 —— 表上你看到的是一行行参数，链上你看到的是一段段环节。（这里只画**形状**；真正的接线规则见 [1.6 连线逻辑](../1-概述与安装部署/1.6-连线逻辑.md)。）

> 💡 上面两个方框是**排版示意**，不是要你照着敲的东西。它们画的是「这两样东西长什么样」，不是「你要执行什么」。

## 0.3.2 差别的根源：那条链路，你能不能改

同一个流程为什么要画成两种样子？因为两个工具对「这条链路归谁」的判断不同。

**WebUI 认为这条链路是固定的。** 它的作者认定「文生图 = 加载模型 → 编码提示词 → 采样 → 解码 → 保存」这条路对绝大多数人够用，于是干脆把它写进界面。你在那张表上看到的每一格，都是这条链路上某一环的**参数入口** —— 链路本身被藏在界面后面，你看不见，也动不了。

**ComfyUI 认为这条链路本身就该交给你。** 画布上那些框就是链路的每一环，线表示「谁把结果交给谁」。于是同一批参数只是换了住处：

| 在 WebUI 里，它是…… | 在 ComfyUI 里，它变成…… |
| --- | --- |
| 表上的一格 | 某个框上的一个值 |
| 一个「生成」按钮 | 一次「把这张工作流交给队列」 |
| 一个你加不进去的新步骤 | 多摆一个框、多连一根线 |

**这就是全部差别。** 你的知识没有作废 —— 提示词怎么写、步数给多少、模型挑哪个，两边完全一样；要换的只是**操作方式**：从「在表上填」变成「在画布上连」。

## 0.3.3 对照表：你原来做的事，现在在哪

把 WebUI 界面上你会碰到的东西逐项搬过来：

| WebUI 里的位置 | ComfyUI 里的对应物 | 变化 |
| --- | --- | --- |
| 模型下拉框 | `Load Checkpoint` 框，选同一个文件 | 换了个地方选 |
| `Prompt` 输入框 | 一个 `CLIP Text Encode` 框里的文字 | 照旧 |
| `Negative prompt` 输入框 | **另一个** `CLIP Text Encode` 框 | 照旧（正、负各一个框） |
| `Width` / `Height` | `Empty Latent Image` 框上的两个值 | 数值照旧 |
| `Steps` / `CFG` / `Sampler` / `Seed` | `KSampler` 框上的几个值 | 数值照旧 |
| `Generate` 按钮 | 把工作流提交进队列 | 换了触发方式 |
| 「保存这组参数」 | 保存**整张工作流**为一个文件 | 从记参数变成存整张图 |
| 装插件加功能 | 装自定义节点包 | 换了个名字，都是社区扩展 |

> 📌 **一句话**：**你在 WebUI 里调的每一项，在 ComfyUI 里都还在。** 没有任何一项能力消失；消失的只是「它们被摆在同一个面板上」这件事。

## 0.3.4 迁移时要改的三个习惯

**1. 出错先看线，而不是先怀疑参数。**
WebUI 出问题几乎总是参数问题 —— 因为链路是固定的，能错的只有你填的值。ComfyUI 多出一类新错误：**线没接对**（接错、漏接、接反）。所以排查的第一步从「参数调小一点」改成「这条链是不是完整的」。这一篇不展开，规则见 [1.6 连线逻辑](../1-概述与安装部署/1.6-连线逻辑.md)。

**2. 参数不再靠记，而是随工作流一起存。**
WebUI 的痛点是换个人、换台机器就得重新报一遍参数。ComfyUI 把整条链存成一个文件，导入即复现。代价是：别人要复现你的图，得有你用到的那些自定义节点包。

**3. 改一处，只需要重跑它后面那段。**
ComfyUI 会记住每个框算过的结果：只要**它的输入没变、上游也没变**，就不重算。所以改一句提示词再生成，不会把模型从头加载一遍。
> ⚠️ 别把这件事和「队列」混起来。这里说的是**一个工作流内部**哪些框要重算；队列说的是**多个任务之间**怎么排队，是另一回事，见 [5.2 队列管理](../5-自动化与批量生成/5.2-队列管理.md)。

## 0.3.5 不用改的部分

- **模型文件是共用的。** 两个工具读同一批模型文件，不必为 ComfyUI 再下一份。放哪见 [2.1 模型放在哪](../2-模型体系与管理/2.1-项目结构与模型存放.md)。
- **出图质量取决于模型，不取决于工具。** 同一个模型、同一组参数，两边生成的图没有本质差别。
- **别同时开两个。** 它们都要占显卡，同时跑容易显存不够。
- **显存不够仍然要处理。** 换工具不会让显卡变大；小显存想跑大模型，靠的是显存策略，见 [7.5 显存优化](../7-性能优化与显存管理/7.5-显存优化.md)。

## 0.3.6 那要不要换？

这套材料从第 0 章起就是按「没接触过 ComfyUI」写的，并不要求你先用过 WebUI。但如果你手上确实有得选，判断标准很实际：

| 你主要想做的事 | 更省事的那个 |
| --- | --- |
| 偶尔生成几张图，不想花时间学界面 | WebUI（表单式，上手即用） |
| 反复微调同一套流程，且要求结果可复现 | **ComfyUI** —— 整条流程可保存、可分享 |
| 想让别的程序调用它批量出图 | **ComfyUI** —— 自带接口，见 [5.4 API 调用](../5-自动化与批量生成/5.4-API调用.md) |
| 想看清每一步到底发生了什么 | **ComfyUI** —— 链路就摆在画面上 |
| 流程长、步骤多、要组合多个模型 | **ComfyUI** —— 加步骤就是加框 |

有一点值得说清楚：**ComfyUI 的「难」是前置的。** 第一次面对空白画布，确实比面对表单更懵；但这份门槛换来的是一条**你看得见、也改得动**的链路。后面的章节，就是带你从零把这条链从头连到尾。
