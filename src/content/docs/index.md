## 这份材料想解决什么问题

多数 ComfyUI 教程是**节点的字典**：把每个节点是什么、有什么参数、怎么连，一条条列出来。这类材料能查，但学不会 —— 因为读者拿到的是一堆**并列的结论**，而不是一条能自己走下去的推理链。

本材料的组织原则相反：

| 原则 | 具体表现 |
|------|---------|
| **提纲挈领** | 不追求面面俱到。不承载推理的内容会被删掉 |
| **兼容两类读者** | 熟悉的人能快速定位，不熟悉的人能不跳跃地跟上 |
| **概念之间有推导链接** | 每个概念都能从前文推出，不做并列罗列 |
| **术语由推导引入** | 先有现象与需求，推到需要命名时才给术语。不先抛术语再解释 |
| **双向自洽** | 每篇都说明它承接了哪篇、又引出了哪篇 |

## 怎么读

**先花三分钟看这一页：** [A7 如何读本文档](./附录/A7-如何读本文档.md)。

它交代三件事：本材料**假设你会什么**（不会的话去哪补）、灰底方框里的内容**分哪三类**（哪类要敲、哪类只要读、哪类根本不要执行）、以及读不懂时**按什么顺序找出口**。后面每一篇都按这套约定写。

**如果你完全没接触过 AI 绘图：**

从 [0.1 什么是 AI 图像生成](./0-零基础入门/0.1-什么是AI图像生成.md) 开始，按侧边栏顺序往下。第 0 章到第 3 章是一条完整的学习路径，走完能独立完成文生图与图生图。

**如果你用过 WebUI，想转 ComfyUI：**

先看 [0.3 与 WebUI 的差异对比](./0-零基础入门/0.3-与WebUI的差异对比.md)，理解两种工具在**思维方式**上的差别（WebUI 是表单，ComfyUI 是数据流），再从 [1.1 Windows 安装](./1-概述与安装部署/1.1-Windows安装.md) 或 [1.2 macOS 安装](./1-概述与安装部署/1.2-macOS安装.md) 接上主线。

**如果你只是来查东西：**

| 想查什么 | 去哪 |
|---------|------|
| 某个节点的中文名（界面是英文的，得能在软件里搜到） | [A2 节点名称中英对照](./附录/A2-节点名称中英对照.md) |
| 某个术语是什么意思 | [A1 术语对照表](./附录/A1-术语对照表.md) —— 它不是词汇表，是**反向索引**：只告诉你"这个词由哪一篇推导出来"，再回那一篇去读 |
| 提示词技巧、版本差异、模型清单、安装参数 | 附录 [A3 提示词技巧速查](./附录/A3-提示词技巧速查.md) – [A6 安装部署参考](./附录/A6-安装部署参考.md) |
| 官方文档在哪一页、公共 API 怎么接 | [A8 官方文档与公共 API 速查](./附录/A8-官方文档与公共API速查.md) —— 官方文档地图、两代 API 的分工、Comfy API v2 与官方 SDK 的最小用法 |

## 章节结构

第 0 到第 3 章是主线，后面按需取用：

| 章节 | 回答什么问题 |
|------|-------------|
| **0. 开始之前** | AI 绘图是怎么回事，ComfyUI 为什么是数据流 |
| **1. 装好、跑通、看懂** | 装起来、跑出第一张图，然后理解刚才那些框和线 |
| **2. 模型** | 那些 .safetensors 文件分别是什么、该放在哪 |
| **3. 提示词与工作流** | 把节点连成能出图的流程，并学会写提示词 |
| **4. ControlNet 精准控制** | 不再靠抽卡，而是控制构图、姿态、人脸 |
| **5. 自动化与批量生成** | 从能出图到能出很多图 |
| **6. 高级节点与插件生态** | 扩展能力边界 |
| **7. 性能优化与显存管理** | 让它跑得更快、不爆显存 |
| **8. 与其他工具集成** | 接进自己的工作流 |
| **9. 团队知识库与任务管理** | 把个人技能变成团队资产 |
| **实战案例** | 25 个由浅入深的完整案例（Level 1–5），与第 3–9 章逐级对应 |
| **附录** | 阅读约定（A7）+ 术语与名称对照、速查与清单 —— 查阅型内容，不占主线序号 |

> 第 4–9 章的编号是**分类**而不是阅读次序：主线走完第 3 章就有了可用的能力，之后按需要取用。
