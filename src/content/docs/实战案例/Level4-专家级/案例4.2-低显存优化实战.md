### 步骤 2: 理解显存模式

**目标：** 理解 ComfyUI 的不同显存模式及其适用场景

#### 2.1 显存模式详解

ComfyUI 提供多种显存模式，从高到低：

| 模式名称 | 启动参数 | 显存需求 | 速度 | 工作原理 |
|---------|---------|---------|------|---------|
| **高显存** | `--highvram` | 12GB+ | 最快 | 所有模型常驻显存 |
| **正常（默认）** | 不加参数 | 8-12GB | 快 | 模型按需加载/卸载 |
| **低显存** | `--lowvram` | 4-8GB | 较慢 | UNet 分段加载 |
| **极低显存** | `--novram` | <4GB | 很慢 | 全部在 CPU 运行 |

#### 2.2 模式选择决策树

| 显存 | 使用模式 |
|---|---|
| > 12GB | 默认模式（最快） |
| 8-12GB | 不加参数（默认模式） |
| 4-8GB | `--lowvram --fp16-unet` |
| < 4GB | `--novram`（或升级硬件） |

### 步骤 4: 优化分辨率设置

**目标：** 理解分辨率与显存的关系，选择合适的分辨率

#### 4.1 分辨率与显存对照表

| 分辨率 | 像素数 | 估算显存需求 | 4GB | 6GB | 8GB |
|-------|-------|-------------|-----|-----|-----|
| 512×512 | 26万 | ~3GB | ✅ | ✅ | ✅ |
| 512×768 | 39万 | ~3.5GB | ⚠️ | ✅ | ✅ |
| 768×768 | 59万 | ~4.5GB | ❌ | ✅ | ✅ |
| 1024×768 | 78万 | ~5.5GB | ❌ | ⚠️ | ✅ |
| 1024×1024 | 104万 | ~7GB | ❌ | ❌ | ⚠️ |

> ✅ = 可正常运行 | ⚠️ = 需要优化配置 | ❌ = 不推荐

#### 4.2 分辨率选择建议

**4GB 显存用户：**
- 推荐分辨率：512×512
- 最大分辨率：512×640
- 技巧：生成小图后使用放大模型放大

**6GB 显存用户：**
- 推荐分辨率：512×768
- 最大分辨率：768×768
- 技巧：使用 Hires.fix 分两步生成

**8GB 显存用户：**
- 推荐分辨率：768×768
- 最大分辨率：1024×1024
- 技巧：可以使用 SDXL（需优化配置）

#### 4.3 分辨率优化技巧

**技巧 1：使用标准分辨率倍数**

SD 1.5 模型训练分辨率为 512×512，推荐使用 64 的倍数：

| 推荐宽度 | 推荐高度 |
|---------|---------|
| 512 | 512, 576, 640, 704, 768 |
| 576 | 512, 576, 640 |
| 640 | 512, 576, 640 |
| 768 | 512, 576, 640, 704, 768 |

**技巧 2：使用 Hires.fix 分步生成**

低显存用户可以：
1. 先生成低分辨率图像（如 512×512）
2. 使用放大模型放大到目标分辨率
3. 这样比直接生成高分辨率更省显存

### 步骤 5: 显存监控与问题排查

**目标：** 学会监控显存使用并排查问题

#### 5.1 实时监控显存

**方法一：使用 nvidia-smi（推荐）**

打开新的命令行窗口，执行：

```bash
nvidia-smi -l 1
```

这会每秒刷新一次显存状态。

**方法二：使用监控脚本**

创建 `monitor_vram.py`：

```python
import torch
import time
import os

def clear_screen():
    os.system('cls' if os.name == 'nt' else 'clear')

def monitor_vram():
    if not torch.cuda.is_available():
        print("CUDA 不可用")
        return
    
    print("="*60)
    print("ComfyUI 显存监控工具")
    print("按 Ctrl+C 退出")
    print("="*60)
    
    total = torch.cuda.get_device_properties(0).total_memory / 1024**3
    
    try:
        while True:
            clear_screen()
            allocated = torch.cuda.memory_allocated(0) / 1024**3
            reserved = torch.cuda.memory_reserved(0) / 1024**3
            free = total - allocated
            
            print("="*60)
            print("ComfyUI 显存监控")
            print("="*60)
            print(f"GPU: {torch.cuda.get_device_name(0)}")
            print(f"总显存: {total:.2f} GB")
            print("-"*60)
            print(f"已使用: {allocated:.2f} GB ({allocated/total*100:.1f}%)")
            print(f"已缓存: {reserved:.2f} GB")
            print(f"可 用: {free:.2f} GB ({free/total*100:.1f}%)")
            print("-"*60)
            
            bar_length = 40
            used_bar = int(allocated / total * bar_length)
            bar = "█" * used_bar + "░" * (bar_length - used_bar)
            print(f"[{bar}] {allocated/total*100:.1f}%")
            print("="*60)
            
            time.sleep(1)
    except KeyboardInterrupt:
        print("\n监控已停止")

if __name__ == "__main__":
    monitor_vram()
```

运行监控：

```bash
python monitor_vram.py
```

#### 5.2 常见显存错误及解决

**错误 1：CUDA out of memory**

```text
RuntimeError: CUDA out of memory. Tried to allocate X.XX GiB
```

**解决方案：**

1. 降低分辨率
2. 添加 `--lowvram` 参数
3. 添加 `--cpu-vae` 参数
4. 减少批量大小

**错误 2：模型加载失败**

```text
RuntimeError: [enforce fail at alloc_cpu.cpp:114]
```

**解决方案：**

1. 检查系统内存是否充足
2. 关闭其他程序
3. 使用更小的模型

**错误 3：生成速度极慢**

**原因分析：**
- 使用了 `--novram` 模式
- CPU 和 GPU 之间频繁数据传输

**解决方案：**
- 尝试升级到 `--lowvram` 模式
- 减少分辨率
- 检查是否有其他程序占用 GPU

## 常见问题

### Q1: 使用 --lowvram 后生成速度变慢很多，正常吗？

**回答：** 是的，这是正常现象。

**原因分析：**
- `--lowvram` 模式需要频繁在 GPU 和 CPU 之间传输数据
- UNet 被分成多个片段，每个片段都需要单独加载

**速度对比：**

| 模式 | 相对速度 | 显存占用 |
|-----|---------|---------|
| 默认 | 100% | 高 |
| --lowvram | 60-80% | 低 |
| --novram | 20-40% | 极低 |

**优化建议：**
- 如果显存允许，不加任何 VRAM 参数即可（这就是默认模式）
- 配合 `--fp16-unet` 可以部分弥补速度损失

### Q2: 生成时出现 "CUDA out of memory" 但显存还有剩余？

**原因分析：**
1. **显存碎片化**：显存虽然总量够，但不连续
2. **瞬时峰值**：生成过程中有瞬时显存峰值
3. **其他程序占用**：浏览器、其他应用占用 GPU

**解决方案：**

```bash
# 方案1：添加 --lowvram 参数
python main.py --lowvram --fp16-unet

# 方案2：关闭浏览器硬件加速
# Chrome: 设置 → 系统 → 关闭"使用图形加速"

# 方案3：重启 ComfyUI 清理显存碎片

# 方案4：检查其他 GPU 占用
nvidia-smi
```

### Q3: 4GB 显存能运行 SDXL 吗？

**回答：** 可以，但需要特殊配置且速度较慢。

**配置方法：**

```bash
python main.py --lowvram --fp16-unet --cpu-vae
```

**限制条件：**
- 分辨率限制在 512×512 或更低
- 生成速度较慢（约 30-60 秒/张）
- 可能需要关闭其他程序

**推荐替代方案：**
- 使用 SD 1.5 模型 + 放大模型
- 使用 SDXL Turbo（更快但质量略低）

### Q4: --cpu-vae 会影响图像质量吗？

**回答：** 不会影响图像质量，只会影响速度。

**工作原理：**
- VAE 在 CPU 上运行，结果与 GPU 完全相同
- 只是计算速度变慢

**速度影响：**
- VAE 解码时间增加 2-5 秒
- 对总体生成时间影响约 10-20%

**建议：**
- 4GB 显存：必须使用
- 6GB 显存：可选使用
- 8GB+ 显存：不需要使用

### Q5: 如何判断应该使用哪个显存模式？

**判断流程：**

按顺序逐档尝试，当前一档仍然显存不足时才进入下一档：

| 顺序 | 尝试 | 何时进入下一档 |
|---|---|---|
| 1 | 不加参数（默认模式） | 出现显存不足 |
| 2 | `--lowvram --fp16-unet` | 仍然不足 |
| 3 | `--lowvram --fp16-unet --cpu-vae` | 仍然不足 |
| 4 | `--novram`（最后选择） | — |

### Q6: 生成高分辨率图像有什么技巧？

**技巧 1：Hires.fix 分步生成**

1. 先生成 512×512 基础图像
2. 使用放大模型放大到 1024×1024
3. 总显存占用比直接生成 1024×1024 低很多

**技巧 2：使用放大模型**

推荐放大模型：
- 4x-UltraSharp
- RealESRGAN_x4plus
- R-ESRGAN 4x+ Anime6B

**技巧 3： tiled VAE**

对于超大图像，使用 tiled VAE 分块处理：
- 安装 ComfyUI-TiledDiffusion 扩展
- 启用 tiled VAE 选项
