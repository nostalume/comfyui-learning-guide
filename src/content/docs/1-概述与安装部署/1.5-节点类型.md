## 1.5.1 一个方块是什么

[1.3](./1.3-启动界面与第一张图.md) 里那张工作流，是一堆方块被线连起来的。**每个方块叫一个 node（节点）。**

节点只做一件事：**吃进若干输入，吐出一个输出。**

```text
        +------------------+
  -->   |                  |   -->
 输入口  |       节点        |  输出口
  -->   |                  |
        +------------------+
```

- 左侧的小圆点叫**输入端口**，右侧的叫**输出端口**；
- 一个节点可以有多个输入口、也可能有多个输出口 —— 取决于它需要几样材料、要交出几样东西；
- **每个端口上都带一个标记，声明它搬运的是什么。** 比如 `Load Checkpoint` 的三个输出口分别标着 `MODEL`、`CLIP`、`VAE`。

那个标记叫**数据类型**。它有多少种、颜色怎么对应、为什么它能决定两根线连不连 —— 是下一篇 [1.6 连线逻辑](./1.6-连线逻辑.md) 的全部内容。**本文只用到「每个口都有一个标记」这一点。**

**每个环节对应一类节点。** 这件事值得停一下：**分类不是软件作者的命名习惯，而是这条链本身逼出来的** —— 少了任何一环，图都出不来。

| 环节 | 对应的节点类 | 这一环解决什么 |
|---|---|---|
| 加载模型 | **取料类** | 把要用的东西从磁盘读进内存 |
| 编码提示词 | **下指令类** | 把一句话变成机器能读的条件 |
| 采样 | **加工类** | 在「半成品」上反复修改 |
| 解码 | **显影类** | 把半成品还原成一张图 |
| 保存 | **交货类** | 让你看到它，或把它落盘 |

下面顺着这条链，一类一类认。**每类里只要认识一两个代表节点就够了**，其余的都是同一件事的变体。

## 1.5.3 一类：取料（把模型和图片读进来）

这一类节点有个共同的样子：**它们不加工任何东西，只是把磁盘上的一个文件读进内存，然后交出去。**

所以它们**没有输入口**（没东西可吃），只有输出口。

| 节点 | 读进来的是什么 | 吐出的标记 |
|---|---|---|
| `Load Checkpoint`（加载模型） | 「大模型」：一套完整的出图能力 | `MODEL`、`CLIP`、`VAE` 三样 |
| `Load LoRA`（加载LoRA） | 一个小补丁，给大模型叠加风格或人物 | `MODEL`、`CLIP` |
| `Load VAE`（加载VAE） | 单独一份图像编解码器 | `VAE` |
| `Load ControlNet Model`（加载ControlNet模型） | 控制模型（管姿势、边缘、深度…） | `CONTROL_NET` |
| `Load Image`（加载图像） | 你硬盘上的一张图（图生图、ControlNet 用） | `IMAGE`、`MASK` |

**五个里只有 `Load Checkpoint` 是必须的** —— 它一次交出 `MODEL`、`CLIP`、`VAE` 三样，是整条链上游的起点。其余四个都是按需补充：要 LoRA 风格才装 LoRA，要控姿势才装 ControlNet。

> 这几样东西各自是什么、有什么区别、从哪下载 —— 是[第 2 章 模型体系与管理](../2-模型体系与管理/2.1-项目结构与模型存放.md) 的主题，本文不展开。这里只需要记住它们**是几类不同的文件，各自有各自的加载节点**：Checkpoint 见 [2.3](../2-模型体系与管理/2.3-Checkpoint大模型.md)、CLIP 见 [2.4](../2-模型体系与管理/2.4-CLIP与T5.md)、VAE 见 [2.5](../2-模型体系与管理/2.5-VAE.md)、LoRA 见 [2.6](../2-模型体系与管理/2.6-LoRA与LyCORIS.md)。

> **为什么「取料」值得单独成为一类？** 因为它和后面四类有个本质区别：**它不产出新数据，只搬运已有数据。** 这个区别下一篇会用到 —— 它正是「改提示词不用重新加载模型，换模型却要重算一大片」的根源（见 [1.6 连线逻辑](./1.6-连线逻辑.md)）。

## 1.5.4 二类：下指令（把一句话变成它能读的条件）

你写下的提示词是**文字**，而采样器要的是**数字**。中间必须有人翻译。

这一类只有一个节点：`CLIP Text Encode`（CLIP文本编码器）。

| 吃什么 | 吐什么 |
|---|---|
| 一个 `CLIP`（从取料类来）+ 一段文字 | `CONDITIONING`（编码后的条件） |

**为什么工作流里总有两个？** 因为它一次只编码一段文字，而采样器要两份条件：

- 一份说「我要什么」→ 接到 `KSampler` 的 `positive`（正向）
- 一份说「我不要什么」→ 接到 `KSampler` 的 `negative`（负向）

所以它俩总是成对出现，框里的文字一正一负。**提示词本身该怎么写**是另一回事，见 [3.3 提示词入门](../3-基础工作流搭建/3.3-提示词入门.md)。

> 负责翻译的这套东西叫 **CLIP**，它就是 `Load Checkpoint` 交出来的三样之一。它凭什么能「读懂」文字，见 [2.4 CLIP与T5](../2-模型体系与管理/2.4-CLIP与T5.md)。

## 1.5.5 三类：加工（在「半成品」上反复改）

这是节点最多、也最核心的一类。但在认节点之前，得先接受一件反直觉的事。

### 它不在像素图上动笔

如果直接在 1024×1024 的图片上做几十轮修改，每一轮都要处理上百万个像素点 —— 又慢又费显存。

所以采样**换了个地方算**：先把图像压进一个小得多的表示里，在小表示上改，改完再还原回图片。那个小表示叫**潜空间（latent）**，端口上的标记就是 `LATENT`；「压小」和「还原」两件事都由 **VAE** 来做。

于是这一类节点几乎全在跟 `LATENT` 打交道：

| 节点 | 做什么 | 吃什么 → 吐什么 |
|---|---|---|
| `Empty Latent Image`（空Latent图像） | 造一块**空白**潜空间当画布（文生图的起点） | 无 → `LATENT` |
| `VAE Encode`（VAE编码） | 把**已有图片**压成潜空间（图生图的起点） | `IMAGE`+`VAE` → `LATENT` |
| `KSampler`（K采样器） | **核心**：按条件与参数，一轮一轮把噪点改成图 | `MODEL`+两个 `CONDITIONING`+`LATENT` → `LATENT` |
| `Apply ControlNet`（应用ControlNet） | 把 ControlNet 的控制条件注入采样过程 | `CONDITIONING`+`CONTROL_NET` → `CONDITIONING` |
| `KSampler Advanced`（高级K采样器） | 同上，但能指定「从第几步算到第几步」 | 同上，另加起止步数 |

**`KSampler` 是整条链上唯一的引擎。** 其余节点都在替它备料，或者给它加限定条件。

> `Empty Latent Image` 与 `VAE Encode` 是**同一个位置的两种填法**：前者凭空造一块干净画布（文生图），后者把一张现成的图压进来（图生图）。换掉这一个节点，工作流的性质就变了 —— 见 [3.2 图生图工作流](../3-基础工作流搭建/3.2-图生图工作流.md)。

> **`Empty Latent Image` 的一条硬约束：** 宽高要是 **8 的倍数** —— 因为潜空间按 8 倍缩小，除不尽就还原不回来。实际使用时大家直接取 **64 的倍数**（512、768、1024…），省得每次算。

> `KSampler` 上 `steps`、`cfg`、`seed` 这些值怎么设、改了会怎样，见 [3.1 文生图工作流](../3-基础工作流搭建/3.1-文生图工作流.md) —— 在那里按「调它会发生什么」讲，比在这里摆一张参数表有用。

## 1.5.6 显影与交货（回到一张能看的图）

### 显影：从潜空间回到一张图

采样结束时，你手上仍然只有一块 `LATENT` —— 那是一堆数字，不是任何看图软件能打开的图片。

于是需要**再翻译一次，方向相反**：把还没显影的中间形态还原成像素图。

| 节点 | 吃什么 → 吐什么 |
|---|---|
| `VAE Decode`（VAE解码） | `LATENT` + `VAE` → `IMAGE` |

**它是整条链上唯一一次类型跨越**（`LATENT` → `IMAGE`）。也正因为跨了这一步，采样阶段「压小」换来的速度才有意义。

> **`VAE Decode` 出问题时图长什么样：** 全黑、全白，或一片彩色噪点。那不是模型不好，是这一步没跑对。排查见 [1.6 连线逻辑](./1.6-连线逻辑.md) 与 [2.5 VAE](../2-模型体系与管理/2.5-VAE.md)。

### 交货：显示，或落盘

最后一步是把 `IMAGE` 交到你手上。两个节点，二选一（也可以都要）：

| 节点 | 结果 |
|---|---|
| `Preview Image`（预览图像） | 只在界面上显示，**不写磁盘** |
| `Save Image`（保存图像） | 写进输出目录，文件名带 `filename_prefix` 前缀 |

> **调试阶段全用 `Preview Image`**，免得输出目录堆满废图；定稿后再换成 `Save Image`。两者的输入口一模一样，可以直接对调。

## 1.5.7 清单之外：为什么还有别的节点

把五类数一遍，核心节点不过十个上下。可搜索面板里有几百个 —— 多出来的那些是什么？

**它们不是新的类别，而是同样这几类的细分与扩展。** 常见的有三个来源：

| 多出来的节点 | 属于哪类 | 为什么会有 |
|---|---|---|
| `Load Image (with mask)`、各种图像处理节点 | 取料 / 加工 | 把图生图、局部重绘这条支线做得更细 |
| `Upscale Image`、`Image Blend` 等 | 加工 | 采样之外还想对图片做后期 |
| 各种 ControlNet **预处理器** | 加工 | 把参考图先加工成 ControlNet 能用的样子，见 [4.3 预处理器类型](../4-ControlNet精准控制/4.3-预处理器类型.md) |
| 满屏你没见过的名字 | —— | **自定义节点包**：社区把新功能做成节点装进来 |

最后一行最常让人困惑：**在文档里找不到某个节点，通常不是漏写了，而是它来自你装的某个扩展包。** 安装方法见 [6.5 自定义节点安装](../6-高级节点与插件生态/6.5-自定义节点安装.md)；一份按名称查的节点清单见 [A2 节点名称中英对照](../附录/A2-节点名称中英对照.md)。

> 判断一个陌生节点属于哪类，办法只有一个：**看它的口。** 没有输入口、只往外吐 → 多半是取料；吃 `LATENT` 又吐 `LATENT` → 加工；吐出 `IMAGE` 而后面没别的节点 → 交货。这个办法下一篇会变成一条正式规则。

## 附录 A 往画布上放一个节点

> **体裁：reference／操作。** 以下是操作，不承担推导 —— 需要时照着做即可。

| 方法 | 步骤 |
|---|---|
| 双击画布空白处 | 打开节点搜索面板 → 输入名称 → 点击或回车 |
| 右键点击画布 | `Add Node` → 按分类浏览 → 找到目标 |
| `Ctrl + F`（macOS 为 `Cmd + F`） | 直接搜索节点名 |

**搜索框只认英文。** 界面上的节点名是英文，而本套文档用 `英文名（中文名）` 的写法称呼它们 —— 原因与完整对照表见 [A2 节点名称中英对照](../附录/A2-节点名称中英对照.md)。

调试时最省力的两个动作（完整键位表见 [1.6 连线逻辑](./1.6-连线逻辑.md) 附录 A）：

- `Ctrl + M` **静音**某个节点，让它沿用上次的结果，相当于临时把这一段摘掉；
- `Ctrl + B` **绕过**某个节点，输入直接透传到输出。
