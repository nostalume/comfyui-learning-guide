## 概述

### 什么是 Benchmark？

Benchmark（基准测试）是一种标准化的性能测试方法，通过在相同条件下运行相同的任务，来测量和比较不同硬件或软件配置的性能表现。

### 为什么需要 Benchmark？

| 用途 | 说明 |
|-----|------|
| **硬件选型** | 了解不同显卡的实际性能，帮助购买决策 |
| **性能对比** | 比较优化前后的速度变化 |
| **问题诊断** | 发现性能瓶颈，定位慢的原因 |
| **预期管理** | 了解自己的硬件能达到什么水平 |

### 本章你将学到什么？

1. 如何阅读和理解性能数据
2. 如何自己进行 Benchmark 测试
3. 影响生成速度的关键因素
4. 如何根据测试结果优化配置

## 测试基准说明

### 标准测试参数

为了保证测试结果的可比性，需要使用统一的测试参数：

| 参数 | 默认值 | 说明 |
|-----|-------|------|
| 模型 | SD 1.5 / SDXL | 使用标准模型，避免特殊模型影响 |
| 分辨率 | 512x512 / 1024x1024 | 固定分辨率，便于对比 |
| 采样步数 | 20 steps | 中等步数，兼顾速度和质量 |
| 采样器 | euler_a | 常用采样器，速度适中 |
| 批量大小 | 1 | 单张生成，排除批量影响 |
| CFG Scale | 7.0 | 标准提示词引导强度 |

### 测试场景说明

| 场景 | 描述 | 复杂度 |
|-----|------|-------|
| **文生图（TXT2IMG）** | 最基础的生成测试 | ⭐ |
| **图生图（IMG2IMG）** | 包含图像编码和解码 | ⭐⭐ |
| **高清修复（Hires Fix）** | 两阶段生成，先小图后放大 | ⭐⭐⭐ |
| **ControlNet** | 额外的条件控制模型 | ⭐⭐⭐ |

## 影响性能的因素

### 硬件因素

| 因素 | 影响程度 | 说明 |
|-----|---------|------|
| GPU 算力 | 🔴 高 | 核心数量和频率决定计算速度 |
| 显存大小 | 🔴 高 | 决定能运行多大的模型 |
| 显存带宽 | 🟡 中 | 影响数据传输速度 |
| CPU 性能 | 🟢 低 | 主要影响预处理和后处理 |
| 内存大小 | 🟢 低 | 低显存模式下较重要 |
| 存储速度 | 🟢 低 | 首次加载模型时影响 |

### 软件因素

| 因素 | 影响程度 | 说明 |
|-----|---------|------|
| 采样步数 | 🔴 高 | 步数越多，时间越长 |
| 分辨率 | 🔴 高 | 分辨率翻倍，时间约 4 倍 |
| 采样器类型 | 🟡 中 | 不同采样器速度差异明显 |
| 批量大小 | 🟡 中 | 批量影响显存和效率 |
| 模型大小 | 🟡 中 | 大模型需要更多计算 |
| ControlNet 数量 | 🟡 中 | 每个 ControlNet 增加计算量 |

## 如何进行 Benchmark 测试（详细步骤）

### 方法一：使用 ComfyUI 内置计时

ComfyUI 会在每个节点执行时自动显示耗时，这是最简单的查看方式。

#### 步骤详解

1. **打开 ComfyUI 界面**
   - 在浏览器中访问 `http://127.0.0.1:8188`

2. **加载工作流**
   - 点击 `Load` 按钮加载你的工作流
   - 或使用默认的文生图工作流

3. **设置测试参数**
   - 在 `Empty Latent Image` 节点设置分辨率（如 512x512）
   - 在 `KSampler` 节点设置步数（如 20）
   - 选择采样器（如 euler_a）

4. **运行生成**
   - 点击 `Queue Prompt` 按钮
   - 观察控制台输出或界面上的节点耗时

5. **查看耗时**
   - 每个节点完成后会显示执行时间
   - 格式示例：`[KSampler] - 1.23s`

#### 节点耗时含义

| 节点名称 | 耗时范围 | 说明 |
|---------|---------|------|
| CheckpointLoaderSimple | 2-10s | 首次加载模型较慢 |
| CLIPTextEncode | <0.1s | 文本编码，很快 |
| KSampler | 1-15s | 主要耗时节点 |
| VAEDecode | 0.1-0.5s | 图像解码 |
| SaveImage | <0.1s | 保存图像 |

### 方法二：使用控制台日志

ComfyUI 在控制台会输出详细的执行日志。

#### Windows 操作步骤

1. **打开命令提示符或 PowerShell**
   - 按 `Win + R`，输入 `cmd` 或 `powershell`

2. **进入 ComfyUI 目录**
   ```bash
   cd E:\ComfyUI
   ```

3. **启动 ComfyUI**
   ```bash
   python main.py
   ```

4. **观察输出日志**
   - 生成时会显示每个节点的执行时间
   - 示例输出：
   ```text
   Prompt executed in 2.35 seconds.
   ```

### 方法三：使用 Python 脚本精确测试

对于需要精确测量的场景，可以使用 Python 脚本。

#### 完整测试脚本

```python
import time
import torch
import sys
sys.path.append("E:/ComfyUI")

def benchmark_generation(pipeline, prompt, steps=20, iterations=5):
    """
    执行多次生成并计算平均时间
    
    参数说明：
    - pipeline: 生成管道
    - prompt: 提示词
    - steps: 采样步数
    - iterations: 测试次数（建议 5-10 次）
    """
    times = []
    
    print(f"开始测试，共 {iterations} 次迭代...")
    print(f"参数：steps={steps}, prompt='{prompt[:30]}...'")
    print("-" * 50)
    
    for i in range(iterations):
        torch.cuda.synchronize()
        start = time.time()
        
        result = pipeline(prompt, num_inference_steps=steps)
        
        torch.cuda.synchronize()
        end = time.time()
        
        elapsed = end - start
        times.append(elapsed)
        print(f"第 {i+1} 次: {elapsed:.2f}s")
    
    avg_time = sum(times) / len(times)
    min_time = min(times)
    max_time = max(times)
    
    print("-" * 50)
    print(f"平均时间: {avg_time:.2f}s")
    print(f"最快: {min_time:.2f}s")
    print(f"最慢: {max_time:.2f}s")
    
    return avg_time

def print_gpu_info():
    """打印 GPU 信息"""
    if torch.cuda.is_available():
        print("=" * 50)
        print("GPU 信息：")
        print(f"  名称: {torch.cuda.get_device_name(0)}")
        print(f"  显存: {torch.cuda.get_device_properties(0).total_memory / 1024**3:.1f} GB")
        print(f"  CUDA 版本: {torch.version.cuda}")
        print("=" * 50)

if __name__ == "__main__":
    print_gpu_info()
```

### 方法四：使用 ComfyUI API 测试

通过 API 调用可以更精确地控制测试流程。

#### API 测试脚本

```python
import requests
import time
import json

class ComfyUIBenchmark:
    def __init__(self, server_url="http://127.0.0.1:8188"):
        self.server_url = server_url
    
    def queue_prompt(self, workflow):
        """提交工作流到队列"""
        response = requests.post(
            f"{self.server_url}/prompt",
            json={"prompt": workflow}
        )
        return response.json()
    
    def wait_for_completion(self, prompt_id, timeout=300):
        """等待生成完成"""
        start_time = time.time()
        while time.time() - start_time < timeout:
            response = requests.get(f"{self.server_url}/history/{prompt_id}")
            if response.status_code == 200 and response.json():
                return True
            time.sleep(0.5)
        return False
    
    def run_benchmark(self, workflow, iterations=5):
        """运行基准测试"""
        times = []
        
        print(f"开始 Benchmark 测试，共 {iterations} 次...")
        
        for i in range(iterations):
            start = time.time()
            
            result = self.queue_prompt(workflow)
            prompt_id = result.get("prompt_id")
            
            if self.wait_for_completion(prompt_id):
                elapsed = time.time() - start
                times.append(elapsed)
                print(f"第 {i+1} 次: {elapsed:.2f}s")
            else:
                print(f"第 {i+1} 次: 超时")
        
        if times:
            print(f"\n平均时间: {sum(times)/len(times):.2f}s")
        
        return times

benchmark = ComfyUIBenchmark()
```

## Benchmark 测试最佳实践

### 测试前准备

| 步骤 | 操作 | 原因 |
|-----|------|------|
| 1 | 重启 ComfyUI | 清除缓存，确保干净环境 |
| 2 | 关闭其他 GPU 程序 | 避免资源竞争 |
| 3 | 等待 GPU 温度稳定 | 温度影响性能 |
| 4 | 首次运行预热 | 加载模型到缓存 |

### 测试注意事项

1. **多次测试取平均值**
   - 单次测试可能受系统波动影响
   - 建议至少运行 5 次取平均

2. **保持环境一致**
   - 相同的驱动版本
   - 相同的 ComfyUI 版本
   - 相同的模型文件

3. **记录详细配置**
   - 记录所有启动参数
   - 记录模型版本
   - 记录工作流设置

## 常见问题 FAQ

### Q1: 为什么我的速度比参考数据慢？

**可能原因及解决方案：**

| 原因 | 检查方法 | 解决方案 |
|-----|---------|---------|
| 未启用加速 | 查看启动日志 | 启用 xFormers 或 SDPA |
| 显存不足 | 检查显存占用 | 使用低显存模式 |
| 驱动过旧 | `nvidia-smi` 查看版本 | 更新 NVIDIA 驱动 |
| 后台程序占用 | 任务管理器检查 | 关闭其他 GPU 程序 |
| 模型未缓存 | 首次运行较慢 | 多次测试取平均值 |

### Q2: 如何判断我的 GPU 性能是否正常？

**判断方法：**

1. 在相同配置下运行测试
2. 对比本章提供的参考数据
3. 如果差距在 20% 以内，属于正常范围
4. 如果差距超过 30%，检查配置是否有问题

### Q3: 批量生成为什么有时候更快？

**原因：**
- GPU 可以并行处理多个样本
- 减少了启动开销
- 更好地利用显存带宽

**注意：**
- 需要足够的显存
- 批量过大反而可能变慢

### Q4: 不同采样器速度差异大吗？

**是的，差异明显：**

| 采样器 | 相对速度 | 推荐场景 |
|-------|---------|---------|
| euler | 最快 | 快速预览 |
| euler_a | 快 | 日常使用 |
| dpmpp_2m | 中等 | 高质量生成 |
| dpmpp_sde | 慢 | 最高质量 |
| uni_pc | 快 | 新算法，推荐尝试 |

### Q5: 如何测试高清修复的速度？

**测试方法：**

1. 使用包含 Hires Fix 的工作流
2. 设置放大倍数（如 1.5x 或 2x）
3. 记录总耗时
4. 分别记录第一阶段和第二阶段耗时

**示例结果：**
```text
第一阶段 (512x512): 1.8s
第二阶段 (1024x1024): 3.2s
总计: 5.0s
```
